# 03.3 门控激活 SwiGLU

出处：CS336 第 3 讲（Tatsu Hashimoto），第 20–26 页。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。部分内容整理自之前关于 SwiGLU 的一段问答。

**术语预备**
- **FFN / MLP**：Transformer 块里注意力之后的那个子层，对每个 token 独立作用。
- **激活函数**：FFN 中间那个逐元素的非线性函数，比如 ReLU $\max(0,z)$、GeLU $z\Phi(z)$（$\Phi$ 是标准正态的分布函数）、Swish（也叫 SiLU）$z\cdot\mathrm{sigmoid}(z)$。
- **门（gate）**：一个取值在某个范围内的量，用来乘另一个量，控制它"放多少过去"。
- **GLU（gated linear unit）**：带门的线性单元。名字里的前缀表示门用的是哪个激活函数：ReGLU 用 ReLU，GeGLU 用 GeLU，SwiGLU 用 Swish。

## 0. 问题：FFN 为什么要变复杂

原始 Transformer 的 FFN 是"线性、激活、线性"：

$$\mathrm{FFN}(x)=\max(0,xW_1)\,W_2 .$$

讲义第 20 页列了一长串激活函数："ReLU, GeLU, Swish, ELU, GLU, GeGLU, ReGLU, SeLU, SwiGLU, LiGLU"。第 21 页给出用法：原始 Transformer、T5、Gopher、Chinchilla、OPT 用 ReLU；GPT-1/2/3、GPT-J、BLOOM 用 GeLU；LLaMA、PaLM、T5 v1.1 以及 2023 年以后的多数模型用 SwiGLU 或 GeGLU。

这篇要回答：SwiGLU 是什么，为什么大家都换了，以及 A1 里 $d_{ff}\approx\tfrac83d$ 是怎么来的。

## 1. 门控是什么

讲义第 22 页的说法："GLUs modify the 'first part' of a FF layer"。把第一层的"线性 + 激活"换成"激活后的一路，逐元素乘上另一路线性"：

$$\max(0,xW_1)\ \longrightarrow\ \max(0,xW_1)\otimes(xV).$$

这就是 ReGLU。把 ReLU 换成 Swish，就是 SwiGLU：

$$\mathrm{FFN}_{\text{SwiGLU}}(x)=\big(\mathrm{Swish}(xW_1)\otimes xV\big)W_2,\qquad\mathrm{Swish}(z)=z\cdot\mathrm{sigmoid}(z).$$

看单个隐藏单元（$w$、$v$ 是 $W_1$、$V$ 的某一列）：
- 普通 FFN：$\sigma(w^\top x)$，一个"脊函数"（只沿 $w$ 一个方向变化）。
- 门控 FFN：$g(w^\top x)\cdot(v^\top x)$，一个脊函数**乘以**一个线性函数。

SwiGLU 的门 $\mathrm{Swish}(z)$ 在 $z\gg0$ 时约等于 $z$，在 $z\ll0$ 时约等于 0。所以每个单元大致是

$$\mathrm{Swish}(w^\top x)\cdot(v^\top x)\approx\mathbf 1[w^\top x>0]\cdot(w^\top x)(v^\top x),$$

**一个只在半空间上打开的二次型**。两个特征相乘，相当于一种软的"与"：条件成立的程度 × 内容。

在 HuggingFace 的 LLaMA 代码里，这三个矩阵分别叫 `gate_proj`（$W_1$）、`up_proj`（$V$）、`down_proj`（$W_2$）。看到权重文件里有 `gate_proj`，基本就能确定是 GLU 一类的结构。

## 2. 证据：一致的、不大的收益

这件事没有理论推导，靠的是实验。讲义第 25 页是 Narang 等人（2020）的对比，同样 223M 参数、同样的计算量，最终 loss（越低越好）：

| FFN | 门 | 最终 loss |
|---|---|---|
| ReLU（基线） | 无 | 1.838 |
| GeLU | 无 | 1.838 |
| Swish | 无 | 1.847 |
| GLU | sigmoid | 1.814 |
| ReGLU | ReLU | 1.803 |
| LiGLU | 恒等（无激活） | 1.798 |
| GeGLU | GeLU | 1.792 |
| SwiGLU | Swish | **1.789** |

讲义第 24 页 Shazeer（2020）在 GLUE 等下游任务上的结论一致。两组数据可以读出三点：

1. **只换激活函数没用.** ReLU、GeLU、Swish 不带门时几乎一样。
2. **加上乘法结构就有用.** 所有带门的变体都比基线好。最说明问题的是 LiGLU：门上根本没有激活函数，每个单元就是两个线性函数相乘，$(w^\top x)(v^\top x)$，也比基线好了 0.04。**收益的大头来自乘法本身。**
3. **sigmoid 门最弱.** 原始的 GLU 用 sigmoid 当门，在带门的变体里最差，比没有激活的 LiGLU 还差。最好的几个（ReGLU、GeGLU、SwiGLU）的门都是 ReLU 一类：正半轴不设上界，负半轴压向 0。

至于 Swish、GeLU、ReLU 三种门之间的差别（1.789、1.792、1.803），已经接近误差的量级，选 Swish 基本是惯例。Gemma 系列用 GeGLU，LLaMA、PaLM、Mistral、OLMo 用 SwiGLU（讲义第 23 页）。

讲义第 26 页的总结很克制："*GLU isn't necessary for a working model (see GPT3)"，但 "evidence points towards somewhat consistent gains"。也有例外，比如 Nemotron 340B 用的是平方 ReLU。

## 3. 为什么 sigmoid 门不如 Swish 门

看单个单元对输入 $x$ 的梯度：

| 单元 | $f(x)$ | $\nabla_xf$ |
|---|---|---|
| ReLU | $\mathrm{ReLU}(w^\top x)$ | $\mathbf 1[w^\top x>0]\,w$ |
| GLU | $(v^\top x)\,\mathrm{sigmoid}(w^\top x)$ | $\mathrm{sigmoid}(w^\top x)\,v+(v^\top x)\,\mathrm{sigmoid}'(w^\top x)\,w$ |
| SwiGLU | $(v^\top x)\,\mathrm{Swish}(w^\top x)$ | $\mathrm{Swish}(w^\top x)\,v+(v^\top x)\,\mathrm{Swish}'(w^\top x)\,w$ |

带门的单元，梯度分成两项：沿 $v$ 的"内容项"，沿 $w$ 的"门项"。

**和 ReLU 比，门控多了门项.** 把 ReLU 写成 $z\cdot\mathbf 1[z>0]$，阶跃函数的导数几乎处处为 0，所以 ReLU 只有内容项。后果是：开关的边界 $\{w^\top x=0\}$ 只能被动地跟着 $w$ 移动，没有任何梯度在说"这个开关应该挪到哪里"；而且 $w^\top x<0$ 时梯度严格为 0，一个单元如果对所有输入都关着，就再也学不动了（"死神经元"）。门控单元的门项正好提供了"开关该往哪挪"的信号。

**sigmoid 门的问题：饱和、有上界.** $\mathrm{sigmoid}'(z)=\mathrm{sigmoid}(z)(1-\mathrm{sigmoid}(z))\le\tfrac14$，而且 $|z|$ 一大就以指数速度趋于 0。所以一个门一旦完全打开或完全关上，$w$ 几乎收不到梯度，门就停止学习了。另外 sigmoid 门最大是 1，只能表示"开或关"，不能表示"开多大"。Swish 门在正半轴上导数趋于 1，不会饱和；它的值随 $w^\top x$ 增长，带有幅度信息。这和 2010 年前后 ReLU 取代 sigmoid 作为激活函数是同一个道理，也和 §2 的数据吻合。

两个细节：Swish 不是处处非负，最小值约 $-0.278$，在 $z\approx-1.28$ 处取到；它和 ReLU 的差 $|z|/(1+e^{|z|})$ 处处不超过 0.278，离开原点后以指数速度趋于 0。

**一个保留.** 以上都是对单个单元的分析。在 Transformer 里，梯度主要沿残差流回传（[[03.1 pre-norm 与 post-norm]]），"门控让梯度更好走"这一点没有那么关键。更重要的解释还是 §2 的实验：在同样的参数量下，门控单元表示的是一类不同的函数，而这类函数更合适。

## 4. 参数对齐：为什么是 8/3

门控 FFN 多了一个矩阵 $V$。讲义第 23 页："Gated models use smaller dimensions for the $d_{ff}$ by 2/3"。算一下参数量：

$$\underbrace{2\cdot d\cdot4d}_{\text{普通 FFN}}=8d^2=\underbrace{3\cdot d\cdot\tfrac83d}_{\text{门控 FFN}} .$$

中间维度从 $4d$ 缩到 $\tfrac83d$，参数量和 FLOPs 都不变。$\tfrac83d$ 一般不是整数，实际会取整到 64 或 256 的倍数，对 GPU 更友好：
- LLaMA 7B：$\tfrac83\times4096=10922.7$，取整到 256 的倍数得 11008。
- A1 的 TinyStories 配置：$\tfrac83\times512=1365.3$，handout 取的是 1344（64 的倍数）。

讲义第 38 页的表里，GLU 类模型的 $d_{ff}/d$ 大多在 2.67 附近（LLaMA 70B 2.68、Qwen 14B 2.67、DeepSeek 67B 2.68），PaLM（4）、LLaMA 2 70B 和 Mistral 7B（3.5）略大。这就是 [[02.4 训练的计算量为什么是 6ND]] 里"每层 $12d^2$ 个参数"对门控 FFN 同样成立的原因。

## 5. 实现

A1 不允许直接用 `torch.nn.functional` 里的激活函数，要自己写：

```python
def silu(z):
    return z * torch.sigmoid(z)                   # Swish / SiLU

def swiglu(x, W1, W2, W3):
    # x: (..., d)；W1、W3: (d_ff, d)；W2: (d, d_ff)。A1 的权重按 (输出维, 输入维) 存
    return (silu(x @ W1.T) * (x @ W3.T)) @ W2.T   # 门 × 内容，再投影回 d 维
```

（A1 里把内容那一路叫 $W_3$，就是上文的 $V$。）

Python 要点：
- `*` 是逐元素乘法，`@` 是矩阵乘法。
- 这样写会额外存一份 $\mathrm{sigmoid}(u)$ 给反向用，显存比内置的 `F.silu` 多一份 $d_{ff}$（[[02.5 训练显存账：参数、梯度、优化器状态、激活]] §2.2）。

很多实现会把 $W_1$ 和 $W_3$ 拼成一个 $d\times2d_{ff}$ 的矩阵，一次矩阵乘法同时算出两路，再切开。这样少一次 kernel 调用，矩阵也更大，更容易跑满 GPU（[[02.3 算术强度与 roofline]]）。

## 6. 总表

| FFN | 公式 | 中间维度 | 谁在用 |
|---|---|---|---|
| ReLU | $\max(0,xW_1)W_2$ | $4d$ | 原始 Transformer、T5、OPT |
| GeLU | $\mathrm{GeLU}(xW_1)W_2$ | $4d$ | GPT-1/2/3、BLOOM |
| GeGLU | $(\mathrm{GeLU}(xW_1)\otimes xV)W_2$ | $\tfrac83d$ | T5 v1.1、Gemma 2/3/4 |
| SwiGLU | $(\mathrm{Swish}(xW_1)\otimes xV)W_2$ | $\tfrac83d$ | LLaMA 1/2/3、PaLM、Mistral、OLMo |

一句话：门控 FFN 把每个隐藏单元从"一个脊函数"变成"脊函数乘线性函数"，收益主要来自这个乘法，再加上去掉 sigmoid 门的上界和饱和；多出的那个矩阵用 $\tfrac83$ 的中间维度抵掉，参数量和计算量不变。

## 练习

1. **推导.** 验证 $|\mathrm{Swish}(z)-\mathrm{ReLU}(z)|=|z|/(1+e^{|z|})$，并说明它在 $|z|\approx1.28$ 处取最大值 0.278。
2. **估算.** LLaMA 2 7B（$d=4096$，$d_{ff}=11008$）每层的 FFN 有多少参数？注意力（4 个 $d\times d$ 矩阵）有多少？FFN 占每层参数的比例是多少？
3. **思考.** LiGLU 的每个单元是 $(w^\top x)(v^\top x)$，整个 FFN 是 $x$ 的二次函数。为什么这样一个"没有激活函数"的 FFN 也能让模型变好？堆很多层以后，它还是二次函数吗？

## 练习答案

1. $z>0$ 时 $\mathrm{ReLU}(z)-\mathrm{Swish}(z)=z(1-\mathrm{sigmoid}(z))=z/(1+e^{z})$；$z<0$ 时 $\mathrm{Swish}(z)-0=z/(1+e^{-z})$，取绝对值得 $|z|/(1+e^{|z|})$。对 $t=|z|$ 求导，令 $(1+e^t)-te^t=0$，数值解 $t\approx1.278$，代入得约 0.278。
2. FFN：$3\times4096\times11008=135.3$M；注意力：$4\times4096^2=67.1$M；FFN 占 66.8%，约三分之二。32 层合计 6.48B，再加上输入、输出两个嵌入矩阵 $2\times32000\times4096=0.26$B，正好是 6.74B。
3. 二次型能直接表示"两个特征同时出现"这种交互，ReLU 单元要用好几个才能近似。堆叠以后就不是二次函数了：每层之间还有归一化（除以一个依赖输入的量）和注意力里的 softmax，整个网络仍然高度非线性。
