# 03.2 从 LayerNorm 到 RMSNorm，以及去掉 bias

出处：CS336 第 3 讲（Tatsu Hashimoto），第 14–19 页。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。计时都在本地 CPU 上测，绝对数字不重要，看比例。

**术语预备**
- **LayerNorm**：对每个 token 的向量 $x\in\mathbb R^d$，减去它自己 $d$ 个分量的均值、除以标准差，再逐分量乘增益 $\gamma$、加偏置 $\beta$。
- **RMSNorm**：只除以均方根（root mean square），不减均值，也没有 $\beta$。
- **bias**：线性层 $xW+b$ 里的那个 $b$。
- **kernel / 融合**：GPU（或 CPU）上执行的一个函数。把几个运算合进一个 kernel 叫融合，好处是数据只从内存里读、写一遍（[[02.3 算术强度与 roofline]] §5）。

## 0. 问题：为什么大家都换成了 RMSNorm

讲义第 14 页的分界很清楚：GPT-1/2/3、OPT、GPT-J、BLOOM 用 LayerNorm；LLaMA 系列、PaLM、Chinchilla、T5 用 RMSNorm。第 15 页给出的现代解释是："it's faster (and just as good)"，因为运算更少（不算均值），参数更少（没有 $\beta$）。

紧接着讲义自己就问："Does this explanation make sense?" 矩阵乘法占了绝大部分 FLOPs，归一化少算一个均值，能快多少？这篇就回答这个问题。

## 1. 两个公式，差在哪里

$$\mathrm{LayerNorm}(x)=\frac{x-\mu}{\sqrt{\sigma^2+\varepsilon}}\odot\gamma+\beta,\qquad \mu=\frac1d\sum_ix_i,\ \sigma^2=\frac1d\sum_i(x_i-\mu)^2.$$

$$\mathrm{RMSNorm}(x)=\frac{x}{\sqrt{\frac1d\sum_ix_i^2+\varepsilon}}\odot\gamma .$$

关系很直接：**LayerNorm 就是先把 $x$ 中心化，再做 RMSNorm，最后加 $\beta$：**

$$\mathrm{LayerNorm}(x)=\mathrm{RMSNorm}(x-\mu\mathbf 1)+\beta .$$

我用 PyTorch 核对过，两边的差是 $10^{-7}$ 量级，就是浮点误差。

几何上，减均值就是把 $x$ 投影到与 $\mathbf 1=(1,\dots,1)$ 正交的超平面上。再用勾股定理 $\lVert x\rVert^2=\lVert x-\mu\mathbf 1\rVert^2+d\mu^2$ 可以看出，只要 $x$ 的均值相对它的大小很小，两种归一化的结果就几乎一样。两者共同的、真正起作用的性质是**对缩放不变**：$\mathrm{Norm}(cx)=\mathrm{Norm}(x)$（$c>0$）。不管上一层的输出被放大还是缩小，下一层看到的大小都是固定的。RMSNorm 保留了这一点，去掉了"对平移不变"。

## 2. FLOPs 不是运行时间

讲义第 16 页引了 Ivanov 等人（2023）对 BERT 的一次剖析：

| 运算类别 | 占 FLOPs | 占运行时间 |
|---|---|---|
| 张量收缩（矩阵乘法） | 99.80% | 61.0% |
| 统计归一化（softmax、LayerNorm 等） | 0.17% | 25.5% |
| 逐元素运算（加法、dropout 等） | 0.03% | 13.5% |

归一化只占 0.17% 的 FLOPs，却花了四分之一的时间。原因正是 [[02.3 算术强度与 roofline]] 讲的：归一化的算术强度很低，属于带宽受限。它的耗时取决于从显存里读写了多少字节，和做了多少次加减乘除几乎无关。讲义的原话是："FLOPS are not runtime!"

所以 RMSNorm 的优势要从"搬了多少数据"来看：
- 少一次归约：LayerNorm 要先算 $\mu$，再算 $\sigma^2$；RMSNorm 只算一次平方和。如果实现上要多扫一遍数据，就是多读一遍整个张量。
- 少一个参数向量 $\beta$ 要读、要存梯度、要存优化器状态。量不大，但省下了一次逐元素加法。

讲义第 17 页引的 Narang 等人（2020）的对比：同样 223M 参数的模型，RMSNorm 每秒 3.68 步，LayerNorm 3.50 步，快 5%；最终 loss 1.821 对 1.838，还略好一点。

## 3. 实测：融合与否比用哪种更重要

在 CPU 上对一个 $16384\times4096$ 的 fp32 张量（256 MB）做归一化，和单纯复制一遍比较：

| 实现 | 时间 | 相对"复制一遍" |
|---|---|---|
| 复制（读一遍、写一遍） | 69 ms | 1.0× |
| LayerNorm，PyTorch 内置（一个融合的 kernel） | 99 ms | 1.4× |
| RMSNorm，`torch.compile` 融合 | 101 ms | 1.5× |
| LayerNorm，`torch.compile` 融合 | 118 ms | 1.7× |
| RMSNorm，逐个运算写（平方、求均值、开方取倒数、相乘） | 270 ms | 3.9× |
| LayerNorm，逐个运算写 | 412 ms | 6.0× |

（这个版本的 PyTorch 在 CPU 上的 `F.rms_norm` 没有专门的融合实现，测出来和逐个运算写的一样慢，273 ms。）

能读出两点：
1. **同样是融合的实现，RMSNorm 比 LayerNorm 快约 15%**（101 对 118 ms），省下的就是那一遍求均值。
2. **融合与否的差别大得多**：逐个运算写，每一步都要把整个张量读一遍、写一遍，耗时是融合版本的 3 到 4 倍。

这正是 A2 要你用 Triton 写一个融合 RMSNorm kernel 的原因（第 6 讲）。

## 4. 去掉 bias

讲义第 18 页："Most modern transformers don't have bias terms." 原始 Transformer 的 FFN 是 $\max(0,xW_1+b_1)W_2+b_2$，现在多数实现写成 $\sigma(xW_1)W_2$。理由也是两条：
- **显存与速度**：和 RMSNorm 去掉 $\beta$ 一样，bias 的参数量很小（每层几个 $d$ 维向量），但每个都意味着一次逐元素加法和相应的读写。
- **优化稳定性**：讲义只列了这一条理由，没有展开。

A1 的线性层也不带 bias。

## 5. 总表

| | LayerNorm | RMSNorm |
|---|---|---|
| 公式 | $(x-\mu)/\sigma\odot\gamma+\beta$ | $x/\mathrm{rms}(x)\odot\gamma$ |
| 对缩放不变 | 是 | 是 |
| 对平移不变 | 是 | 否 |
| 每层参数 | $2d$ | $d$ |
| 归约次数 | 两次（均值、方差） | 一次（平方和） |
| FLOPs 占比 | 可忽略 | 可忽略 |
| 运行时间 | 带宽受限，看读写次数 | 同左，少一次归约 |
| 谁在用 | GPT-1/2/3、OPT、BLOOM | LLaMA、PaLM、T5、多数现代 LM |

一句话：RMSNorm 是去掉中心化和偏置的 LayerNorm，保留了真正有用的"对缩放不变"；它省的不是 FLOPs，而是归一化这种带宽受限运算里的读写次数，所以能快几个百分点、效果不差。要真正快起来，关键是把归一化融合成一个 kernel。

## 练习

1. **推导.** 证明 $\mathrm{LayerNorm}(x)=\mathrm{RMSNorm}(x-\mu\mathbf 1)+\beta$（取相同的 $\gamma$、$\varepsilon$）。再证明两者都满足 $\mathrm{Norm}(cx)=\mathrm{Norm}(x)$（$c>0$，忽略 $\varepsilon$）。
2. **估算.** 一个融合的 RMSNorm kernel 至少要读、写多少字节？在 H100 上（3.35 TB/s），对一个 $8192\times4096$ 的 bf16 张量，它至少要多少时间？一次 $8192\times4096$ 乘 $4096\times4096$ 的 bf16 矩阵乘法至少要多少时间？
3. **思考.** §3 里逐个运算写的 RMSNorm 包含 4 个运算。估算它一共要读写多少次整个张量，并和实测的 3.9 倍比较。

## 练习答案

1. 记 $y=x-\mu\mathbf 1$，它的均值是 0，所以 $\frac1d\sum y_i^2=\sigma^2$，于是 $\mathrm{RMSNorm}(y)=y/\sqrt{\sigma^2+\varepsilon}\odot\gamma$，加上 $\beta$ 就是 LayerNorm。缩放不变：$cx$ 的均值是 $c\mu$，标准差和均方根都是原来的 $c$ 倍，分子分母同时乘 $c$，比值不变。
2. 至少读一遍、写一遍：$2\times8192\times4096\times2$ 字节 = 134 MB，除以 3.35 TB/s，约 40 微秒。矩阵乘法要 $2\times8192\times4096\times4096=2.7\times10^{11}$ FLOPs，按 989 TFLOP/s 约 280 微秒。归一化的 FLOPs 只有矩阵乘法的千分之一左右，时间却是它的七分之一。
3. 平方：读 1 写 1；求均值：读 1（结果很小）；开方取倒数：可忽略；相乘：读 1 写 1（再乘 $\gamma$ 又是读 1 写 1）。合计约读 4 次、写 3 次，是复制（读 1 写 1）的 3.5 倍左右，和实测的 3.9 倍相近。
