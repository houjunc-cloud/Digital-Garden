# 02.5 训练显存账：参数、梯度、优化器状态、激活

出处：CS336 第 2 讲（Percy Liang），`motivating_questions`、`optimizer` 两节；每参数字节数对照了第 8 讲第 17、28 页。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。激活的数字用 PyTorch 在本地逐项实测过。

**术语预备**
- **参数 / 梯度**：模型的权重，以及 loss 对每个权重的导数。两者一一对应，个数相同。
- **优化器状态**：优化器为每个参数额外记的东西。Adam 记两个：梯度的滑动平均 $m$（一阶矩）和梯度平方的滑动平均 $v$（二阶矩）。AdaGrad 只记一个。
- **主权重（master weights）**：混合精度训练里那份 fp32 的参数，更新都累加在它上面（[[02.1 浮点格式：为什么训练用 bf16]] §4.2）。
- **激活（activation）**：前向时每一层的中间结果。反向要用其中一部分，所以前向时要存着，直到反向用完。
- **$d$, $d_{ff}$, $h$, $n$, $L$, $V$**：模型宽度、FFN 中间层宽度、注意力头数、序列长度、层数、词表大小。

## 0. 问题：一块 80 GB 的卡能训多大的模型

讲义开头的第二个问题："What's the largest model that you can train on 8 H100s using AdamW?" 讲义的算法：

$$\frac{8\times80\ \text{GB}}{12\ \text{字节/参数}}=53\text{B 参数},$$

后面紧跟一句提醒："activations are not accounted for … so this is an upper bound"。

这篇把这笔账算完整。显存分两块，性质完全不同：
1. **跟着参数走的**：参数、梯度、优化器状态。大小只取决于模型有多少参数，和喂多少数据无关。
2. **跟着 token 走的**：激活。大小和一次喂进去的 token 数成正比。

## 1. 跟着参数走的：每个参数 12 还是 16 字节

讲义的 12 字节是：bf16 参数 2 + bf16 梯度 2 + fp32 的 $m$ 4 + fp32 的 $v$ 4。课程里还出现过几种算法：

| 方案 | 参数 | 梯度 | 主权重 | $m$ | $v$ | 合计 |
|---|---|---|---|---|---|---|
| 第 2 讲开头的估算 | 2 | 2 | — | 4 | 4 | **12** |
| 第 8 讲第 17 页（标准混合精度） | 2 | 2 | 4 | 4 | 4 | **16** |
| 第 8 讲第 28 页（只有主权重是 fp32） | 2 | 2 | 4 | 2 | 2 | **12** |
| PyTorch autocast（参数本身就是 fp32） | 4 | 4 | 参数本身 | 4 | 4 | **16** |
| A1 handout 的假设（全 fp32） | 4 | 4 | — | 4 | 4 | **16** |

第 2 讲的 12 字节里没有主权重。[[02.1 浮点格式：为什么训练用 bf16]] §4.2 说明了只存 bf16 参数的风险：训练后期学习率变小以后，更新会被舍入掉。所以第 8 讲把主权重加了回去，变成 16 字节。第 8 讲第 28 页的 12 字节是另一种省法：主权重保留 fp32，把 $m$、$v$ 降到 bf16，那一页注明要配合 Kahan 求和这类补偿舍入误差的技巧。

**记一个数就行：每个参数 16 字节。** 这是最常见的情形，A1 也按这个算。

**"8 张 H100 训 53B" 还有一个隐含前提.** 把 640 GB 当成一整块用，要求参数、梯度、优化器状态平均切到 8 张卡上，每张卡只存 1/8。这是第 8 讲的 ZeRO 第 3 阶段（也叫 FSDP）。最朴素的数据并行是每张卡存一份完整的拷贝，那么上限就是单卡的 $80/16=5$B。第 8 讲第 28 页的表里，同样是 8 张 80 GB 的卡、12 字节/参数，朴素做法是 6.7B，ZeRO-3 是 53B，正好对上讲义这个数。

讲义里还有一个小例子（`optimizer` 一节）：3 层、每层 $4\times4$，共 48 个参数，AdaGrad。账本是：参数 96 字节（bf16），梯度 96 字节，优化器状态 192 字节（AdaGrad 每个参数一个 fp32 状态），激活 48 字节，合计 432 字节。

## 2. 跟着 token 走的：激活

### 2.1 为什么要存激活

反向传播时，每一层算梯度都要用到前向时的某些中间结果。最典型的是 [[02.4 训练的计算量为什么是 6ND]] §2 里的权重梯度 $\partial\ell/\partial W=x^\top G$：要用到这一层的输入 $x$。前向从第 1 层算到第 $L$ 层，反向从第 $L$ 层倒回来，所以第 1 层的输入要一直存到反向的最后。于是**所有层的激活会同时待在显存里**，峰值出现在前向刚结束、反向刚开始的时候。

讲义提到的对比："For inference, we don't compute gradients, so we only need to store the current layer's activations." 推理时算完一层就可以把上一层的扔掉，所以推理的显存比训练小得多（KV cache 另算，见第 10 讲）。

### 2.2 逐项清点：每层每个 token 存了什么

我按 A1 的架构（pre-norm、RMSNorm、RoPE、因果注意力、SwiGLU）写了一个 Transformer 块，然后遍历 PyTorch 的反向计算图，把每个节点为反向存下来的张量列出来（同一块内存只算一次，参数不算）。用 PyTorch 内置的 softmax、SiLU 时，每层每个 token 存的是：

| 谁要存 | 存的是什么 | 每个 token 的元素数 |
|---|---|---|
| 两个 RMSNorm | 各自的输入 $x$ 和归一化后的 $x/\text{rms}$ | $4d$ |
| 各个线性层 | $W_Q,W_K,W_V$ 的共同输入、$W_O$ 的输入、$W_1,W_3$ 的共同输入 | $3d$ |
| 注意力的两次矩阵乘法 | 算 $QK^\top$ 要 $Q$、$K$；算 $PV$ 要 $V$ | $3d$ |
| softmax 之后的注意力权重 $P$ | 每个头对每个 token 存一行，长 $n$ | $h\cdot n$ |
| SwiGLU | $W_1$ 的输出 $u$（SiLU 要用）、SiLU 的输出、$W_3$ 的输出、两者的乘积（$W_2$ 的输入） | $4d_{ff}$ |

合起来：

$$\text{每层每 token}\approx10d+4d_{ff}+h\cdot n\ \text{个数}.$$

RoPE 的 cos、sin 表和因果掩码也会被存下来，但它们和 batch 无关，可以忽略。实测（$d=512$、$d_{ff}=1344$、$h=16$）和公式的对照：

| 序列长 $n$ | 实测（元素/token/层） | $10d+4d_{ff}+hn$ |
|---|---|---|
| 128 | 12642 | 12544 |
| 256 | 14722 | 14592 |
| 512 | 18882 | 18688 |

差的那 100 个左右就是掩码和 cos/sin 表。

**两个要点.**
- 取 $d_{ff}=\tfrac83d$（A1 的设定），$4d_{ff}\approx10.7d$，FFN 存的比注意力部分还多，合计约 $20.7d+hn$。
- $h\cdot n$ 这一项随序列长度增长，所以总的激活随 $n$ **平方**增长。$n$ 一长，它就是大头。FlashAttention 不存 $P$，反向时重算，于是这一项就没了（[[05.5 FlashAttention：分块加在线 softmax]]）。第 8 讲第 46 页也说："As with flash attention, we can drop this term via recomputation"。

**自己写的算子存得更多.** A1 要求自己实现 softmax（减最大值、取 exp、除以和）和 SiLU（$x\cdot\sigma(x)$）。我用同样的方法测了这个版本，每层每 token 多出 $2hn+d_{ff}$：
- 取最大值那一步要存输入 $s$，除法那一步要存 $e^s$，各一份 $n\times n$，再加上最终的 $P$。
- SiLU 多存一份 $\sigma(u)$。

PyTorch 内置的 softmax 只存输出，因为它的反向只要输出就够了：$\partial p_i/\partial s_j=p_i(\delta_{ij}-p_j)$。这就是内置算子（"融合"的版本）省显存的原因。

### 2.3 模型之外：logits

最后的 RMSNorm 和输出层，每个 token 存约 $3d$ 个数。交叉熵存的是 log-softmax 的输出，每个 token $V$ 个数，一般用 fp32。词表大的时候，这一项不能忽略。比如 Llama 3 的词表是 128256，8192 个 token 光 logits 就有 $8192\times128256\times4$ 字节 = 4.2 GB。

## 3. 两笔账放在一起

**总公式**（$T$ = 一次喂进去的 token 数，$b$ = 激活每个元素的字节数）：

$$\text{显存}\approx\underbrace{16N}_{\text{参数、梯度、优化器状态}}+\underbrace{T\cdot b\cdot\big[L(10d+4d_{ff}+hn)+V+3d\big]}_{\text{激活}}.$$

**谁更大？** 忽略 $hn$，取 $d_{ff}=\tfrac83d$、bf16 激活（$b=2$），每个 token 的激活约 $41.3Ld$ 字节；参数约 $12Ld^2$ 个，占 $192Ld^2$ 字节。两者相等时

$$T\approx4.6d.$$

$d=4096$ 时只要约 19000 个 token，也就是不到 5 条长 4096 的序列。真实训练每一步是几百万个 token（当然要分到很多卡上），所以**激活通常才是大头**。

**算例 1：A1 的 TinyStories 配置**（$d=512$、4 层、$h=16$、$n=256$、$V=10000$、全 fp32）。
- 跟着参数走的：$22.7\text{M}\times16=363$ MB。
- 激活：每个 token $4\times14592+11536\approx70000$ 个数，280 KB。一个 batch 64 条序列、16384 个 token，就是 4.6 GB，是前者的 12 倍多。

**算例 2：Llama 2 7B**（$d=4096$、$L=32$、$h=32$、$d_{ff}=11008$、$n=4096$，bf16 激活）。
- 跟着参数走的：$6.74\text{B}\times16=108$ GB，单张 80 GB 的卡已经放不下了。
- 激活：每层每 token 432 KB，其中 $P$ 占 262 KB。32 层，一条 4096 长的序列要 **57 GB**。不存 $P$（FlashAttention）也要 22 GB，再加 logits 0.7 GB。

所以训练 7B 这种规模的模型，单卡连一条序列都放不下。要靠第 8 讲的各种切分，把参数状态和激活分到多张卡上；还要靠 [[02.6 梯度累积与激活重计算]] 把激活压下来。

## 4. 怎么量

**GPU 上**，讲义用的是 PyTorch 自带的峰值统计：

```python
torch.cuda.reset_peak_memory_stats()
loss = model(x).sum(); loss.backward()
print(torch.cuda.max_memory_allocated())   # 这段时间里显存占用的最高点（字节）
```

**CPU 上，或者想知道具体存了什么**，可以用 PyTorch 的钩子（hook）拦下每一个"为反向而存"的张量。这篇的数字就是这么量的：

```python
def activation_bytes(model, run):
    params = {p.untyped_storage().data_ptr() for p in model.parameters()}
    seen = {}
    def pack(t):                                  # 每个要为反向保存的张量都会经过这里
        st = t.untyped_storage()                  # 张量背后真正的那块内存
        if st.data_ptr() not in params:           # 参数本来就在，不算激活
            seen[st.data_ptr()] = st.nbytes()     # 同一块内存只记一次
        return t
    with torch.autograd.graph.saved_tensors_hooks(pack, lambda t: t):
        run()                                     # 在钩子生效期间跑一次前向
    return sum(seen.values())

# 用法：activation_bytes(model, lambda: F.cross_entropy(model(x).view(-1, V), y.view(-1)))
```

Python 要点：
- `saved_tensors_hooks(pack, unpack)` 让你在"存"和"取"两个时刻插入自己的函数。这里 `pack` 只是记账，原样返回，不改变任何计算。
- 用"内存块的地址"去重，是因为很多张量只是同一块内存的不同视图（比如 `q.view(...)`、`x[..., 0::2]`）。按张量个数算会重复。

## 5. 总表

| 部分 | 大小 | 随什么变 | 怎么压 |
|---|---|---|---|
| 参数 + 梯度 + 优化器状态 | 约 $16N$ 字节 | 只随模型大小 | 切到多张卡上（ZeRO / FSDP，第 8 讲） |
| 激活：各层的线性部分 | 每层每 token 约 $(10d+4d_{ff})\cdot b$ | token 数 × 层数 | 重计算、梯度累积（[[02.6 梯度累积与激活重计算]]） |
| 激活：注意力权重 $P$ | 每层每 token $hn\cdot b$ | 还随 $n$ 增长 | FlashAttention 不存它 |
| logits | 每 token 约 $4V$ 字节 | token 数 × 词表 | 分块计算交叉熵 |

一句话：显存一半跟着参数走，每个参数约 16 字节；一半跟着 token 走，每层每个 token 约 $10d+4d_{ff}+hn$ 个数。真实训练里后者才是大头，所以讲义那个 53B 只是上界。

## 练习

1. **推导.** 解释为什么 softmax 的反向只需要它的输出 $P$，不需要输入 $s$。由此说明内置 softmax 比"减最大值、exp、除以和"三步手写版本少存了什么。
2. **估算.** 一个 $d=2048$、$L=24$、$h=16$、$d_{ff}=5504$ 的模型，序列长 $n=2048$，bf16 激活。每条序列的激活是多少 GB？其中 $P$ 占多少？
3. **估算.** 第 2 讲 `gradient_accumulation` 一节估算激活时用的是 $2\cdot B\cdot D\cdot L$ 字节（每层只存一个 $B\times D$ 的张量）。这对它的那个"线性层 + ReLU"玩具网络是对的，对 Transformer 差了多少倍？
4. **A1 对应.** A1 的 `adamw_accounting` (a)(b) 就是用这篇的方法给 GPT-2 XL 记账，题目已经列好了激活要数哪些部分，并且假设全 fp32。注意题目列的 "$QK^\top$ matrix multiply, softmax" 是否意味着打分矩阵和 $P$ 各存一份，自己判断后在答案里写明。

## 练习答案

1. $p=\text{softmax}(s)$ 的雅可比是 $\partial p_i/\partial s_j=p_i(\delta_{ij}-p_j)$，只含 $p$。所以反向公式 $\partial\ell/\partial s=p\odot(g-\langle g,p\rangle)$（$g=\partial\ell/\partial p$）只用到 $p$。手写的三步里，取最大值那一步存了输入 $s$，除法那一步存了 $e^{s}$ 和分母，于是多存了两份 $n\times n$ 的矩阵，正好是 §2.2 实测的 $2hn$。
2. 每层每 token $10\cdot2048+4\cdot5504+16\cdot2048=20480+22016+32768=75264$ 个数，乘 2 字节约 150 KB。乘 24 层、2048 个 token，约 7.4 GB，其中 $P$ 占 $32768/75264\approx44\%$，约 3.2 GB。
3. Transformer 每层每 token 存约 $20.7d+hn$ 个数，玩具网络是 $d$ 个。不算 $P$ 也差了约 20 倍，序列一长差得更多。
4. 留给 A1 自己做。
