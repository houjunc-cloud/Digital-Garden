# 02.4 训练的计算量为什么是 6ND

出处：CS336 第 2 讲（Percy Liang），`gradients_flops` 一节。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。文中的数字都在本地重算过，FLOP 计数用 PyTorch 自带的计数器实测。

**术语预备**
- **FLOP**：一次浮点加法或乘法。**FLOPs** 是次数（工作量），**FLOP/s** 是每秒次数（硬件速度）。两个词读音一样，差一个"除以时间"。
- **前向 / 反向（forward / backward）**：前向是从输入一路算到 loss；反向是从 loss 往回用链式法则算梯度。训练一步 = 前向 + 反向 + 优化器更新参数。
- **激活（activation）**：每一层的中间输出。反向要用到它们，所以前向时要存下来。
- **$N$、$D$**：参数量；训练用的 token 总数。宽度（隐藏维度）用小写 $d$，别和 $D$ 混了。
- **MFU**：实际达到的 FLOP/s 除以硬件标称峰值。0.5 已经算很好。

## 0. 问题：不跑就知道要算多久

讲义开头的问题：在 1024 张 H100 上，用 15T token 训一个 70B 参数的模型，要多久？

答案只要一行：

$$C\approx6ND=6\times(70\times10^9)\times(15\times10^{12})=6.3\times10^{24}\ \text{FLOPs}.$$

H100 的 bf16 稠密峰值约 $989\times10^{12}$ FLOP/s（规格表上的 1979 是带稀疏的数字，稠密要减半）。MFU 取 0.5，1024 张卡每天能做 $989\times10^{12}\times0.5\times1024\times86400\approx4.4\times10^{22}$ FLOPs，所以要约 **144 天**。

这个算法成立，靠两件事：
1. 训练的时间主要花在大矩阵乘法上，而大矩阵乘法是 compute-bound 的（见 [[02.3 算术强度与 roofline]]），所以"时间 ≈ FLOPs ÷ 有效速率"。
2. 训练一共要做多少 FLOPs，有一个和架构细节几乎无关的公式 $6ND$。

这篇讲第 2 件事：6 是怎么来的（前向 2，反向 4），为什么对 Transformer 也成立，以及它在哪几处会数错。

## 1. 前向：每个参数，每个 token，一次乘加

**命题 1.** 设 $x\in\mathbb R^{B\times d_{in}}$（$B$ 个数据点），$W\in\mathbb R^{d_{in}\times d_{out}}$。算 $y=xW$ 需要 $2Bd_{in}d_{out}$ FLOPs，也就是

$$\text{前向 FLOPs}=2\times(\text{数据点数})\times(\text{参数数}).$$

*理由.* $y_{ik}=\sum_jx_{ij}W_{jk}$，每个三元组 $(i,j,k)$ 贡献一次乘法、一次加法。换个角度数：每个权重 $W_{jk}$ 对每个数据点 $i$ 恰好参与一次乘加。所以总数只和"参数个数 × 数据点个数"有关，和矩阵长什么形状无关。∎

（严格说，$d_{in}$ 项求和只要 $d_{in}-1$ 次加法，精确值是 $Bd_{out}(2d_{in}-1)$。差别可以忽略，后面都按 $2Bd_{in}d_{out}$ 算。）

一个网络如果主要由线性层组成，把各层加起来就是 $2BN$。层与层之间的非线性（ReLU、GeLU）、归一化、残差加法都是逐元素运算，每层 $O(Bd)$；线性层是 $O(Bd^2)$（$d$ 是宽度）。$d=4096$ 时前者小三个数量级，忽略。

### 在 Transformer 里，"数据点"就是 token

Transformer 里有参数的矩阵（$W_Q,W_K,W_V,W_O$ 和 FFN 的几个矩阵）都是**逐位置**作用的：同一组权重，分别乘到序列里每个位置的向量上。所以一个形状为 (batch, 序列长度, $d$) 的激活张量，对这些矩阵乘法来说就是一个有 batch × 序列长度 行的矩阵。在这里，序列维和 batch 维没有区别。

于是"数据点数"就是 token 数，处理 $D$ 个 token 的前向是 $2ND$。讲义写的"6 (# data points) (# parameters)"，在语言模型里读作 6 × token 数 × 参数量。

唯一让不同位置互相看见的，是注意力里的 $QK^\top$ 和"注意力权重乘 $V$"两步。它们没有参数，$6ND$ 里不含它们，§4.1 单独算。

## 2. 反向：要算两样东西，每样都和前向一样贵

还是 $y=xW$。反向时，上面一层传下来 $G=\partial\ell/\partial y\in\mathbb R^{B\times d_{out}}$。这一层要算两样东西：

| 要算的 | 公式 | 形状 | FLOPs | 给谁用 |
|---|---|---|---|---|
| 权重梯度 | $\partial\ell/\partial W=x^\top G$ | $(d_{in}\times B)(B\times d_{out})$ | $2Bd_{in}d_{out}$ | 优化器，用来更新 $W$ |
| 输入梯度 | $\partial\ell/\partial x=GW^\top$ | $(B\times d_{out})(d_{out}\times d_{in})$ | $2Bd_{in}d_{out}$ | 下面一层，链式法则要往下传 |

两样都省不了：没有权重梯度，这一层没法更新；没有输入梯度，下面所有层都拿不到自己的梯度。每一样都是一次和前向一样大的矩阵乘法，所以

$$\text{反向}=2\times\text{前向}=4\times(\text{数据点数})\times(\text{参数数}).$$

**换成数学的说法.** 前向是一个双线性映射 $\beta(x,W)=xW$。它的微分是 $d\beta=dx\,W+x\,dW$，有两个偏导：$\partial_x\beta:X\mapsto XW$ 和 $\partial_W\beta:V\mapsto xV$。反向传播做的事，就是把 $G$ 喂给这两个偏导的**伴随**：

$$(\partial_x\beta)^*G=GW^\top,\qquad(\partial_W\beta)^*G=x^\top G.$$

"右乘一个矩阵"的伴随是"右乘它的转置"，"左乘 $x$"的伴随是"左乘 $x^\top$"，都是同样大小的矩阵乘法，代价和前向一样。**双线性 → 两个偏导 → 两次同样大的矩阵乘法**，这就是反向的那个 2。它和网络的具体结构无关：凡是"数据 × 权重"形式的运算，前向付 1 份，反向付 2 份。

讲义在两层网络上核对了这两个公式：`h1.grad` 等于 `h2.grad` 乘 `w2` 的转置，`w2.grad` 等于 `h1` 的转置乘 `h2.grad`。我用 PyTorch 的 FLOP 计数器（`torch.utils.flop_counter.FlopCounterMode`）在 $L$ 层线性网络上实测，$B=1024$、宽度 $d=256$，单位是一次前向矩阵乘法 $2Bd^2$：

| 层数 $L$ | 前向 | 反向（输入不要梯度） | 反向 / 前向 | 反向（输入也要梯度） | 反向 / 前向 |
|---|---|---|---|---|---|
| 1 | 1 | 1 | 1.000 | 2 | 2.000 |
| 2 | 2 | 3 | 1.500 | 4 | 2.000 |
| 4 | 4 | 7 | 1.750 | 8 | 2.000 |
| 16 | 16 | 31 | 1.938 | 32 | 2.000 |

左半边是个小细节：第一层的输入是数据，没人需要它的梯度，PyTorch 会跳过那次矩阵乘法，所以反向是 $2L-1$ 份而不是 $2L$ 份。层数一多，这点差别就看不见了。Transformer 的第一步是查嵌入表（不是矩阵乘法，见 §4.2），之后每个矩阵乘法的输入都是激活，都要梯度，所以比例就是 2。

## 3. 合起来：$C\approx6ND$

每个 token：前向 $2N$，反向 $4N$，共 $6N$。$D$ 个 token：

$$C\approx6ND.$$

优化器更新那一步呢？AdamW 对每个参数做十几次逐元素运算，一步大约 $15N$ FLOPs，而且和这一步处理多少 token 无关。一步里的 token 数（batch × 序列长度）通常是百万量级，前向加反向是 $6N\times10^6$，优化器那点可以忽略。

公式反过来用也方便：给定算力预算 $C$ 和模型大小 $N$，能训的 token 数就是 $C/(6N)$。Chinchilla 的"$D\approx20N$"就是在这个约束下求最优（见 [[09.3 Chinchilla 与 D≈20N]]）。

## 4. 它在哪里数不准

$6ND$ 数的是"数据 × 权重"的乘法。下面几种情况，要么有不属于这一类的运算，要么 $N$ 该数哪些参数说不清。

### 4.1 注意力：没有参数，但不是没有计算

$QK^\top$ 和"注意力权重 × $V$"是**激活乘激活**，里面没有参数，$6ND$ 看不见它们。

单独算一层、一个 token。设序列长 $n$，所有头的维度加起来是 $d$。位置 $t$ 的 query 要和 $t$ 个 key 做点积（$2td$ FLOPs），再对 $t$ 个 value 加权求和（又是 $2td$）。因果掩码下 $t$ 从 1 到 $n$，平均 $n/2$，所以前向约 $2nd$。这两步也是矩阵乘法，反向同样是前向的 2 倍，训练合计约 $6nd$。

再估一下 $N$。每层：注意力四个 $d\times d$ 矩阵，$4d^2$；FFN 两个 $d\times4d$ 矩阵，$8d^2$；共 $12d^2$。（SwiGLU 有三个矩阵，取 $d_{ff}=\tfrac83d$ 时也正好是 $8d^2$。第 3 讲列的 GLU 类模型，$d_{ff}/d$ 大多在 $8/3\approx2.67$ 附近，就是这个原因，见 [[03.3 门控激活 SwiGLU]]。）$L$ 层共 $N\approx12Ld^2$。于是

$$C\approx6ND\Big(1+\frac{n}{12d}\Big).$$

修正项只看"序列长度 / 宽度"。用真实配置算一下（$N$ 按实际的矩阵精确计，含 GQA 和输出层，所以和 $n/12d$ 略有出入）：

| 模型 @ 训练长度 | $d$ | 注意力额外开销 / $6ND$ | $n/(12d)$ |
|---|---|---|---|
| GPT-3 175B @ 2K | 12288 | 1.4% | 1.4% |
| Llama 2 7B @ 4K | 4096 | 8.1% | 8.3% |
| Llama 3 70B @ 8K | 8192 | 7.7% | 8.3% |
| Llama 3 8B @ 8K | 4096 | 14% | 17% |
| 同上，序列拉到 128K | 4096 | 229% | 267% |
| A1 TinyStories @ 256 | 512 | 3.0% | 4.2% |

所以讲义那句"对短上下文的 Transformer 也是很好的近似"，条件是 $n\ll12d$。模型越宽，同样长的上下文越不显眼，这也是 [[01 课程总览与 tokenization]] 里 Roller 那张表的规律（规模越大，attention 占比越小）。反过来，上下文拉到 128K，注意力的计算比所有矩阵乘法加起来还多，真实计算量是 $6ND$ 的 3.3 倍。

两个细节：
- 上面假设实现会跳过被掩掉的那一半（FlashAttention 就是这么做的）。如果老老实实算完整的 $n\times n$ 矩阵再盖掉一半，前向是 $4nd$，修正项变成 $n/(6d)$。
- 我在一个小 GPT（A1 TinyStories 的形状，算完整的 $n\times n$ 打分矩阵）上实测了总训练 FLOPs。$n=256$、1024、4096 时，实测值 ÷ $6ND$ 分别是 1.0597、1.2387、1.9548，和 $1+\tfrac{12Lnd}{6N}$ 对到小数点后四位。

### 4.2 词表：$N$ 到底数哪些参数

模型两头各有一个和词表一样大的矩阵，性质完全不同：
- **输入嵌入**：用 token 编号去查一张 $V\times d$ 的表，就是"按下标取一行"，几乎没有 FLOPs。它有 $Vd$ 个参数，但这些参数不参与矩阵乘法。
- **输出层**（把最后的隐藏向量变成词表上的 logits）：一个真正的 $d\times V$ 矩阵乘法，每个 token 前向 $2Vd$。

所以 $6ND$ 里的 $N$ 应该是**所有参与矩阵乘法的参数**：各层的矩阵 + 输出层，不含输入嵌入。（如果输入、输出共用同一个矩阵，也就是"权重绑定"，就按一份算。）

大模型上这点差别无所谓，GPT-3 的嵌入矩阵不到总参数的 0.4%。小模型上就要紧了。A1 的 TinyStories 配置（$V=10000$、$d=512$、4 层）：

| 部分 | 参数 |
|---|---|
| 4 个 Transformer 块 | 12.46M |
| 输出层 | 5.12M |
| 输入嵌入 | 5.12M |
| 总计 | 22.70M |

A1 handout 说这个模型"约 17M 非嵌入参数"，正好是 12.46M + 5.12M：它把输出层算进来、把输入嵌入排除在外，和上面的规则一致。如果拿总参数 22.7M 代进 $6ND$，会多算约 22%。

### 4.3 激活重计算：硬件实际做了 8ND

第 2 讲最后讲的激活重计算（[[02.6 梯度累积与激活重计算]]）为了省显存，前向时不存某些激活，反向时再算一遍。全部重算的话，硬件实际做的是"前向 + 前向 + 反向" $=8ND$。

惯例是 MFU 的分子仍按 $6ND$ 算。重算是系统为了省显存做的选择，不是模型本身需要的计算，所以 MFU 衡量的是"有用的工作"占硬件峰值的比例。开了重计算，MFU 会显得低一些，这是诚实的。

### 4.4 MoE：$N$ 是"激活参数"

MoE 模型每个 token 只经过其中几个专家，其余专家的参数对这个 token 不做任何乘法。所以 $N$ 要换成**每个 token 实际用到的参数**。例如 DeepSeek-V3 总参数 671B、每个 token 激活 37B，估算训练算力要用 37B（见 [[04.4 MoE：参数多、计算少]]）。

### 4.5 其余可以忽略的

- 逐元素运算（归一化、激活函数、softmax、RoPE、残差加法）：以 Llama 2 7B 估，每层每 token 几十万 FLOPs，而矩阵乘法是四亿多，约千分之一。上面的 FLOP 计数器只数矩阵乘法，也是这个原因。
- 第一层不需要输入梯度（§2 表里的 $2L-1$）。
- 优化器那一步（§3）。

## 5. 自己数一遍

想核对自己的模型，可以直接让 PyTorch 数：

```python
import torch
from torch.utils.flop_counter import FlopCounterMode

def train_flops(model, batch, loss_fn):
    """返回 (前向 FLOPs, 反向 FLOPs)。只数矩阵乘法一类的运算。"""
    fc = FlopCounterMode(display=False)
    with fc:
        loss = loss_fn(model(batch))
    fwd = fc.get_total_flops()

    fc = FlopCounterMode(display=False)
    with fc:
        loss.backward()
    return fwd, fc.get_total_flops()

# 在 meta 设备上建模型：只推形状，不分配内存，不做真实计算。
# 几十亿参数的模型，在笔记本上也能数。
with torch.device("meta"):
    model = ...   # 你的 TransformerLM
```

拿到结果后和 $6N\times(\text{token 数})$ 比，比值应该接近 $1+12Lnd/(6N)$（完整打分矩阵的情形）。差得多的话，通常是 $N$ 数错了（把输入嵌入算进去了），或者模型里有你没想到的大矩阵乘法。

Python 要点：
- `with fc:` 是上下文管理器。在这个代码块里执行的每个 PyTorch 运算，都会被计数器拦下来累计 FLOPs。
- 在 `torch.device("meta")` 下建的张量只有形状和类型，没有数据。FLOP 数只取决于形状，所以够用。

## 6. 总表

| 运算 | 每 token 前向 | 训练 | $6ND$ 是否计入 |
|---|---|---|---|
| 各层的权重矩阵（注意力投影、FFN） | $2N_{\text{层}}$ | $6N_{\text{层}}$ | 是 |
| 输出层 | $2Vd$ | $6Vd$ | 是，只要 $N$ 里数了它 |
| 输入嵌入 | ≈ 0 | ≈ 0 | 否，$N$ 里也不该数它 |
| 注意力打分与加权求和 | $2nd\cdot L$（因果） | $6nd\cdot L$ | 否，要另加；$n\ll12d$ 时可忽略 |
| 逐元素运算 | $O(d)$ | $O(d)$ | 否，约千分之一 |
| 激活重计算 | — | 再加一次前向 $2N$ | 否，MFU 惯例也不计 |
| 优化器更新 | — | 每步约 $15N$，不随 token 数增长 | 否，可忽略 |

一句话：每个权重对每个 token，前向做一次乘加（2）；反向因为"数据 × 权重"是双线性的，要对两个因子各求一次伴随（4）；合起来 $6ND$。它数的只是"数据 × 权重"。"激活 × 激活"的注意力、查表的输入嵌入、为省显存重算的那一遍，都要另算。

## 练习

1. **估算.** A1 的 TinyStories 配置要处理 327,680,000 个 token。用 $6ND$ 加上注意力修正，估算总 FLOPs。B200 的 bf16 稠密峰值是 $2.25\times10^{15}$ FLOP/s，fp32 是 $7.5\times10^{13}$。handout 说，正确且高效的实现在一张 B200 上要跑 20–30 分钟。这说明了什么？
2. **推导.** 证明 §2 表格左半边：$L$ 层线性网络、输入不要梯度时，反向是 $2L-1$ 份，比值是 $(2L-1)/L$。每层后面接 ReLU，结论变不变？
3. **估算.** Llama 2 7B 的训练长度从 4K 拉到多长时，注意力的计算会和所有矩阵乘法一样多？
4. **A1 对应.** A1 的 `transformer_accounting` 和 `adamw_accounting` 的 (c)(d) 两问，就是本篇方法在 GPT-2 系列上的应用：先列出前向的全部矩阵乘法，再用"反向 = 2 × 前向"得到训练 FLOPs。

## 练习答案

1. $N=17.57$M（4 个块 + 输出层），$6ND=3.46\times10^{16}$。注意力再加 $6LndD=6\cdot4\cdot256\cdot512\cdot3.28\times10^8\approx1.0\times10^{15}$，合计约 $3.56\times10^{16}$。按 bf16 峰值只要 16 秒，按 fp32 峰值约 8 分钟。实际要 20–30 分钟，意味着用 bf16 的话 MFU 只有 1% 左右。原因是模型太小：$512\times1344$ 的矩阵喂不饱 GPU，时间大量花在 memory-bound 的逐元素运算、kernel 启动和数据搬运上（[[02.3 算术强度与 roofline]]）。$6ND$ 告诉你"至少要算多少"，MFU 告诉你"算得有多浪费"，两个合起来才是时间。
2. 第 $\ell$ 层（$\ell\ge2$）的输入是激活，要算输入梯度和权重梯度，共 2 份；第 1 层的输入是数据，只要权重梯度，1 份。合计 $2(L-1)+1=2L-1$，前向 $L$ 份。接 ReLU 不变：ReLU 的反向是乘一个 0/1 掩码，是逐元素运算，不是矩阵乘法。
3. 粗估 $n/(12d)=1$，$n=12\times4096\approx49$K。按精确的 $N$（6.61B，含输出层）解 $6Lnd=6N$，得 $n=N/(Ld)\approx50$K。
4. 留给 A1 自己做。
