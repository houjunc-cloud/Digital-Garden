# 03.5 超参数的共识：FFN 倍数、头维度、宽深比、词表大小

出处：CS336 第 3 讲（Tatsu Hashimoto），第 36–47、51 页。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。词表实验用的是 A1 测试数据里的 TinyStories 样本，在本地训练 BPE。

**术语预备**
- **$d$（d_model）**：残差流的宽度。
- **$d_{ff}$**：FFN 中间层的宽度。
- **$h$、$d_{\text{head}}$**：注意力头的个数、每个头的维数。
- **$L$（n_layer）**：层数。**宽深比**指 $d/L$。
- **$V$**：词表大小。**压缩率**：平均每个 token 对应多少字节（[[01 课程总览与 tokenization]] §5.1）。

## 0. 问题：这些数是怎么定的

讲义第 36 页列了几个"上 CS224N 时可能想问的问题"：FFN 该比隐藏层大多少？头数是否必须整除 $d$？词表多大？模型该深还是该宽？

讲义的发现是，各家模型在这些问题上出奇地一致。这篇逐个看共识是什么、有多少证据，以及为什么偏偏是这些值。

## 1. FFN 倍数：$d_{ff}=4d$，门控时 $\tfrac83d$

讲义第 37 页："$d_{ff}=4d_{\text{model}}$. This is almost always true." 例外主要有两类：
- **门控 FFN**：多了一个矩阵，为了参数量不变，缩到 $\tfrac83d\approx2.67d$（[[03.3 门控激活 SwiGLU]] §4）。第 38 页的表里，LLaMA 70B 是 2.68，Qwen 14B 2.67，DeepSeek 67B 2.68，Yi 34B 2.85，T5 v1.1 2.5；PaLM（4）、LLaMA 2 70B 和 Mistral 7B（3.5）略大一些。
- **T5 11B**：$d=1024$，$d_{ff}=65536$，64 倍。讲义的评价是 "very bold"。它的后继 T5 v1.1 改回了 2.5 倍（GeGLU），说明 64 倍大概不是最优的。最近的例外还有 Gemma 2 的 8 倍。

**证据.** 讲义第 40 页引了 Kaplan 等人（2020）的实验：**总参数固定**（5000 万），只改 $d_{ff}/d$，看 loss 增加多少。比值在 1 到 10 之间，loss 几乎不变；超过 10 才明显变差，到几十倍时已经差了约 8%。

所以 4 不是一个精心找到的最优点，而是一个宽平底里的普通位置。真正的约束只有两条：别太小，也别太大。

## 2. 头数 × 头维度 = $d$

讲义第 42 页：大多数模型满足 $h\cdot d_{\text{head}}=d$，也就是把宽度 $d$ 平均分给各个头。第 43 页的表（比值是 $h\cdot d_{\text{head}}/d$）：

| 模型 | 头数 | 头维度 | $d$ | 比值 |
|---|---|---|---|---|
| GPT-3 | 96 | 128 | 12288 | 1 |
| T5 | 128 | 128 | 1024 | 16 |
| T5 v1.1 | 64 | 64 | 4096 | 1 |
| LaMDA | 128 | 128 | 8192 | 2 |
| PaLM | 48 | 258 | 18432 | 0.67 |
| LLaMA 2 | 64 | 128 | 8192 | 1 |
| Qwen 3.5 (27B) | 24 | 256 | 5120 | 1.2 |

（讲义原表 PaLM 一行的比值写的是 1.48。按表里的数，$48\times258=12384<18432$，照其他行的算法比值应是 0.67；1.48 是把比值倒过来算了，即 $18432/12384$。这里按其他行的算法改了过来。）

**为什么这么分.** 取 $h\cdot d_{\text{head}}=d$，注意力的四个投影矩阵仍然是 $d\times d$，参数量 $4d^2$、FLOPs 和单头注意力一样。多头只是把同样的预算切成 $h$ 份，换来 $h$ 种不同的注意力模式，代价是每个头的打分矩阵 $QK^\top$ 秩不超过 $d_{\text{head}}$。

讲义第 51 页对这一条的评价是 "standard – but low to no validation"：大家都这么做，但没有什么实验证明它最好。表里的例外（T5、LaMDA、PaLM）也都训得很好。

**为什么头维度多是 128.** 这更多是工程上的选择：
- 128 是 GPU 矩阵乘法分块大小的整数倍，注意力 kernel 对 64、128 这类头维度做了专门优化。
- KV cache 的大小正比于 $d_{\text{head}}$ 乘以 KV 头数（[[03.8 GQA 与 MQA：为 KV cache 省显存]]）。

## 3. 宽深比：$d/L$ 在 100 到 200 之间

讲义第 44 页：

| 模型 | $d/L$ |
|---|---|
| BLOOM | 205 |
| T5 v1.1 | 171 |
| PaLM (540B) | 156 |
| GPT-3 / OPT / Mistral / Qwen / OLMo 3 | 128 |
| LLaMA / LLaMA 2 | 102 |
| Gemma 3 | 87 |
| Gemma 4 | 61 |
| T5 (11B) | 33 |

**证据.** 第 46 页 Kaplan 等人的图：5000 万、2.7 亿、15 亿参数三种规模下，$d/L$ 从十几到两百多，loss 都差不多（"A wide range of architectures achieve similar performance"）。

**那 128 是怎么来的.** 讲义第 45、51 页的答案是 "Systems concerns dictate the value"：
- **深度没法并行.** 第 $l$ 层必须等第 $l-1$ 层算完。层数越多，单个 token 的延迟越长；跨卡切分时只能用流水线并行，会有气泡（第 8 讲）。
- **宽度容易并行.** 一层里的矩阵乘法可以切到很多张卡上同时算（张量并行）。

在 loss 差不多的一个宽范围里，系统上的考虑决定了具体取哪个值。

**一个实用公式.** 每层约 $12d^2$ 个参数（[[02.4 训练的计算量为什么是 6ND]] §4.1），总参数 $N\approx12Ld^2$。固定宽深比 $d/L=a$，得 $N\approx12d^3/a$，所以

$$d\approx\Big(\frac{aN}{12}\Big)^{1/3},\qquad L=d/a .$$

取 $a=128$ 验算：

| $N$ | 公式给出的 $d$、$L$ | 实际模型 |
|---|---|---|
| 7B | 4211、32.9 | LLaMA 2 7B：4096、32 |
| 13B | 5176、40.4 | LLaMA 2 13B：5120、40 |
| 175B | 12313、96.2 | GPT-3：12288、96 |
| 70B | 9072、70.9 | LLaMA 2 70B：8192、80（$a=102$） |

前三个几乎完全对上。要设计一个新模型，先定参数量，取 $a=128$ 算出 $d$，再取整到 128 的倍数，就是一个合理的起点。

## 4. 词表大小：单语 3–5 万，多语 10–25 万

讲义第 47 页：
- **单语模型**：原始 Transformer 37000、GPT 40257、GPT-2/3 50257、T5 32128、LLaMA 32000。
- **多语或产品级模型**：mT5 250000、PaLM 256000、GPT-4 100276、Gemma 4 262144、DeepSeek 100000、Qwen 15B 152064、Yi 64000。

讲义的结论："Monolingual vocabs don't need to be huge, but multilingual ones do."

**词表大小在权衡什么.**
- **好处：压缩率更高.** 词表越大，常见的字节串越多地变成一个 token，同样的文本切出的 token 越少。序列短了，注意力便宜，同样的上下文窗口能装更多文本。
- **代价：参数和计算.** 输入嵌入和输出层各是 $V\times d$。输出层还是一次真正的矩阵乘法，每个 token 要算 $2Vd$ FLOPs，logits 还要占 $V$ 个数的显存（[[02.5 训练显存账：参数、梯度、优化器状态、激活]] §2.3）。小模型受影响最大：A1 的 TinyStories 配置里，输出层占了参与矩阵乘法的参数的 29%；LLaMA 3 8B（$V=128256$）只占 7%。
- **代价：罕见 token 学不好.** 词表越大，每个 token 在训练数据里出现得越少。

**实测：压缩率很快饱和.** 在 4.5 MB 的 TinyStories 文本上训练不同大小的 BPE 词表，测量同领域留出文本和另一份英文语料上的压缩率：

| 词表大小 | TinyStories（同领域） | 另一份英文语料 |
|---|---|---|
| 512 | 2.39 | 1.76 |
| 1000 | 3.12 | 2.08 |
| 2000 | 3.63 | 2.34 |
| 4000 | 3.91 | 2.57 |
| 8000 | 4.04 | 2.81 |
| 11352（训练数据能支持的上限） | 4.06 | 2.91 |
| GPT-2 的词表 50257（在网页文本上训练） | 3.94 | 4.31 |

能读出三点：
1. **收益递减很快.** 同领域里，词表从 512 涨到 2000，压缩率涨了 50%；从 4000 涨到 8000，只多 3%。A1 给 TinyStories 定的 $V=10000$ 已经在平台上了。
2. **压缩率取决于训练 tokenizer 的数据.** 只在儿童故事上训练的词表，换到别的英文文本上压缩率掉了三成；GPT-2 的词表在网页上训练，对这两份文本都比较好。
3. **多语为什么要大词表**，道理是一样的：每种语言都要占一份"常见字节串"的名额。语言越多，要达到同样的压缩率，词表就得越大。

**取整.** 词表大小一般会补到 64 或 128 的倍数，让输出层的矩阵乘法形状对 GPU 友好。比如 GPT-2 的 50257 是个奇数，有些实现会把它补到 50304（$=64\times786$），多出来的那些 token 永远不会被用到。

## 5. 总表

| 超参数 | 共识 | 证据 | 为什么是这个值 |
|---|---|---|---|
| $d_{ff}/d$ | 4；门控 $\tfrac83$ | Kaplan：1 到 10 之间都差不多 | 宽平底里的惯例；门控时保持参数量不变 |
| $h\cdot d_{\text{head}}/d$ | 1 | 几乎没有验证 | 参数量和 FLOPs 与单头相同；$d_{\text{head}}=128$ 对 kernel 友好 |
| $d/L$ | 100–200，常见 128 | Kaplan：十几到两百多都差不多 | 系统考虑：深度难并行、延迟高 |
| $V$ | 单语 3–5 万；多语 10–25 万 | 压缩率很快饱和 | 压缩率与参数、计算之间的权衡；语言越多越大 |

一句话：这几个形状超参数，loss 在很宽的范围内都差不多，所以各家都选了一个惯例值，再按系统上的方便取整；真正需要想清楚的只有词表，它在压缩率和参数、计算之间权衡，答案取决于要覆盖多少种语言。

## 练习

1. **估算.** 用 §3 的公式，为一个 1B 参数的模型选 $d$ 和 $L$（取 $a=128$，$d$ 取整到 128 的倍数）。如果 $d_{\text{head}}=128$，有几个头？门控 FFN 的 $d_{ff}$ 取多少？
2. **估算.** 一个 $d=2048$、$V=128256$ 的模型，输入嵌入和输出层各有多少参数？如果总参数约 1.2B，它们占多大比例？
3. **思考.** §1 里 Kaplan 的实验是在**总参数固定**的前提下改 $d_{ff}/d$。如果不固定总参数，单纯把 $d_{ff}$ 从 $4d$ 加到 $8d$，loss 会怎样？这能说明 $8d$ 更好吗？

## 练习答案

1. $d=(128\times10^9/12)^{1/3}\approx2200$，取 2176 或 2304；取 $d=2048$ 也合理（取整到 2 的幂），此时 $L=16$，$N\approx12\times16\times2048^2=0.8$B，再加上嵌入就在 1B 上下。$h=2048/128=16$。门控 $d_{ff}\approx\tfrac83\times2048=5461$，取整到 256 的倍数得 5376 或 5632。
2. 每个 $128256\times2048\approx263$M。两个（不共享时）合计 525M，占 1.2B 的 44%；输入、输出共用一个矩阵时是 263M，占 22%。小模型配大词表，嵌入会占掉很大一块参数。
3. loss 多半会下降，因为参数变多了。但这只说明"参数多了更好"，不能说明 8 倍这个形状更好。要比较形状，必须固定参数量（或者固定算力），这就是 Kaplan 那个实验的设计，也是第 9 讲 scaling law 里反复用到的思路。
