# 02.6 梯度累积与激活重计算

出处：CS336 第 2 讲（Percy Liang），`gradient_accumulation`、`activation_checkpointing` 两节；"重计算能自己付账"一句来自第 8 讲第 62 页。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。文中的数字都用 PyTorch 在本地实测过。

**术语预备**
- **batch / micro-batch**：一次参数更新用的全部数据 / 把它切开后的一小份。
- **梯度累积（gradient accumulation）**：一份一份地算梯度并加起来，攒够一整批再更新参数。
- **激活重计算（activation recomputation）**：也叫 activation checkpointing、gradient checkpointing、rematerialization，讲义把四个名字都列了。前向时只存一部分激活，反向时缺的再算一遍。
- **检查点（checkpoint）**：重计算方案里保留下来的那些激活，通常是某一段网络的输入。

## 0. 问题：batch 想要大，激活装不下

[[02.5 训练显存账：参数、梯度、优化器状态、激活]] 的结论是：激活和一次喂进去的 token 数成正比，真实训练里它是显存的大头。另一方面，讲义说 "Large batch sizes: improve training stability"，batch 不能随便缩小。

两种办法都不碰参数、梯度、优化器状态，只压激活：
- **梯度累积**：用时间换。
- **激活重计算**：用计算换。

## 1. 梯度累积：切成几份，梯度加起来

### 1.1 为什么等价

一批 $B$ 个样本的 loss 是平均值 $\mathcal L=\frac1B\sum_{i=1}^B\ell_i$。把它切成 $k$ 份，每份 $B/k$ 个，第 $j$ 份的平均 loss 记为 $\mathcal L_j$，那么

$$\nabla\mathcal L=\frac1k\sum_{j=1}^k\nabla\mathcal L_j .$$

梯度是线性的，整批的梯度就是各份梯度的平均。所以可以一份一份地算：每份做一次前向、反向，把梯度加到一起，最后更新一次。激活只需要装下一份，降为原来的 $1/k$。

PyTorch 写起来很简单，因为 `.backward()` 默认就是把梯度**加到** `.grad` 上，而不是覆盖：

```python
opt.zero_grad()
for x, y in micro_batches:                  # k 份
    loss = loss_fn(model(x), y) / k         # 除以 k：k 份的平均才是整批的平均
    loss.backward()                         # 梯度累加到每个参数的 .grad 上
opt.step()                                  # 攒够一整批，更新一次
opt.zero_grad()                             # 清零，下一批重新攒
```

我在一个小 GPT 上核对过：一次算 8 条序列的梯度，和切成 4 份、每份 2 条累积起来的梯度，相对差 $2.6\times10^{-7}$，就是 fp32 的舍入误差。

讲义的步骤是："Compute gradient on micro batches; accumulate the gradients (don't zero it out); every batch_size / micro_batch_size steps, update the parameters and zero out the gradients"。

### 1.2 代价

- **FLOPs 不变**：样本还是那些样本。
- **时间可能变长**：$k$ 份是一份接一份算的。每份要足够大，GPU 才跑得满。按 [[02.3 算术强度与 roofline]]，每次矩阵乘法要有几百个 token 才够，一条几千 token 的序列就已经满足。所以实际上 micro-batch 可以切得很小，几乎没有损失。
- **参数、梯度、优化器状态不变**：梯度累积省不了这部分。

**讲义 trace 上的一个小问题.** trace 页面显示的是旧版代码，里面写的是 `micro_batch_size = 256`，比 `B = 64` 还大，所以算出来的激活从 2 MB 变成了 8 MB，反而变多了。GitHub 上的现行代码已经改成 `micro_batch_size = B / 4`，结果是 0.5 MB。

### 1.3 陷阱：平均的单位

上面的等价性有一个前提：每份的 loss 都是在**同样多**的单位上取平均。语言模型的 loss 是在 token 上取平均的。如果各份里有效 token 数不同（比如序列长短不一、末尾补了填充 token），"先在每份里平均、再在份之间平均"就不等于"在所有 token 上平均"了。

实测：两份数据，A 份有 240 个有效 token，B 份只有 20 个。
- 每份先取平均再平均：B 份的每个 token 权重被放大了 6.5 倍，梯度和正确值的相对差是 **165%**。
- 正确做法：每份的 loss 先**求和**，再除以整批的总 token 数。这样和整批一次算的结果一致。

```python
n_tokens = sum((y != PAD).sum() for _, y in micro_batches)   # 先数整批一共多少有效 token
for x, y in micro_batches:
    loss = F.cross_entropy(model(x).flatten(0, 1), y.flatten(),
                           ignore_index=PAD, reduction="sum") / n_tokens
    loss.backward()
```

预训练通常把文本拼接后切成等长的序列，每份 token 数一样，碰不到这个问题。后训练（SFT）的数据长短不一，就会碰到。

## 2. 激活重计算：只存检查点，反向时再算

### 2.1 做法

前向时，把网络分成若干段，只保存每一段的输入（检查点），段内的中间激活算完就扔。反向走到某一段时，先从它的检查点把这一段的前向重跑一遍，得到段内的激活，再对这一段做反向，做完就扔掉，接着处理上一段。

讲义的说法："Philosophy: tradeoff memory for compute"。PyTorch 里用 `torch.utils.checkpoint.checkpoint(段函数, 输入)` 包一下就行。

### 2.2 讲义里的演示为什么一点没省

讲义在一个 16 层的玩具网络上（每层是"乘 $1024\times1024$ 的矩阵，再接 ReLU"，$B=64$）比较了两种情况，trace 里 H100 上记录的峰值显存是：
- 不重计算：202.1 MB
- 每层一个检查点：202.9 MB

**反而多了.** 原因有两个。

第一，**这个网络的每一层本来就只存它的输入.** 反向时，矩阵乘法要用它的输入 $x$，ReLU 要用它的输出，而这个输出正是下一层的输入。所以不重计算时，每层存的就是一个 $B\times D$ 的张量，也就是这一层的输入。每层设一个检查点，存的还是每层的输入，一模一样。反向时还要再重算出一份，所以略多一点。

第二，**这个配置下激活本来就小.** 16 个 $64\times1024$ 的 fp32 张量一共 4 MB，而参数和梯度各是 $16\times1024^2\times4$ 字节 = 67 MB。就算把激活全部省掉，峰值也降不了多少。

### 2.3 每隔几层设一个检查点：√L

讲义接着问："How frequently to checkpoint?" 设网络有 $L$ 层，每层的激活算 1 份，每 $k$ 层设一个检查点：
- 前向结束时，存着 $L/k$ 个检查点。
- 反向处理某一段时，要把这一段的 $k$ 层激活重算出来。

峰值约为

$$\frac Lk+k,$$

在 $k=\sqrt L$ 时取最小值 $2\sqrt L$。讲义列的三种情况：

| 方案 | 显存 | 额外计算 |
|---|---|---|
| 每层都存（不重计算） | $O(L)$ | 0 |
| 什么都不存，每层都从头重算 | $O(1)$ | $O(L^2)$ |
| 每 $\sqrt L$ 层存一个 | $O(\sqrt L)$ | $O(L)$，即多一次前向 |

我把讲义的玩具网络放大到 $B=32768$（让激活成为大头），在 CPU 上测了真实的峰值内存，单位是"一个 $B\times D$ 的 fp32 张量"（128 MB）：

| 每段层数 $k$ | 预测 $L/k+k$ | 实测峰值 | 实测 − 预测 |
|---|---|---|---|
| 不重计算 | 16 | 17.1 | 1.1 |
| 1（讲义的做法） | 17 | 18.2 | 1.2 |
| 2 | 10 | 11.3 | 1.3 |
| **4** $=\sqrt{16}$ | **8** | **9.3** | 1.3 |
| 8 | 10 | 11.5 | 1.5 |
| 16 | 17 | 18.2 | 1.2 |

实测比预测一律多出 1 份左右，那是反向时临时的梯度张量。曲线在 $k=4$ 处最低，两边对称，显存只有不重计算时的一半多一点。$k=1$ 和 $k=16$ 都和不重计算差不多：前者检查点太多，后者一段太长。

### 2.4 Transformer：在块的边界设检查点就够了

玩具网络里，"检查点"和"段内激活"一样大，所以只能省到 $\sqrt L$。Transformer 不一样。[[02.5 训练显存账：参数、梯度、优化器状态、激活]] 算过，一个块每 token 要存约 $10d+4d_{ff}+hn$ 个数，而块的输入只有 $d$ 个。在每个块的入口设一个检查点，就能省掉 95% 以上。

实测 A1 形状的模型（4 层、$d=512$），每个 token 为反向存下的元素数：

| | 4 个块 | 输出层与 logits | 合计 |
|---|---|---|---|
| 不重计算 | 58632 | 11541 | 70173 |
| 每块一个检查点 | **2048**（$=L\cdot d$） | 11541 | 13589 |

块的部分正好降到 $L\cdot d$，即每层只留一个输入。反向时还要临时装下一个块重算出来的激活（约 14700），所以峰值约是原来的 40%。这个小模型的词表相对宽度很大，剩下的大头变成了 logits，那部分没有被检查点覆盖。

换成 Llama 2 7B（$d=4096$、32 层、bf16），每 token 的激活从 13.8 MB 降到：检查点 $32\times4096\times2$ 字节 = 262 KB，加上一个块的重算 432 KB，再加 logits 177 KB，共约 0.87 MB，是原来的 1/16。

### 2.5 代价：多一次前向

重计算相当于把前向再做一遍，训练 FLOPs 从 $6ND$ 变成约 $8ND$，最多多 33%（[[02.4 训练的计算量为什么是 6ND]] §4.3）。在上面那个 A1 形状的模型上实测是多 19%，少于 33% 有两个原因：
- 输出层没有被检查点覆盖，不用重算。这个小模型里它占前向 FLOPs 的 27.5%。
- PyTorch 重算时，算到"后面要用的激活都已经回来了"就停。块里最后一个矩阵乘法（$W_2$）的输出反向用不到，所以它不会被重算。

两项扣掉以后，和实测完全对得上。

按惯例，MFU 的分子不算这多出来的一遍（[[02.2 数 FLOPs：矩阵乘法的 2mnk 与 MFU]] §4）。

### 2.6 只重算划算的那部分

不必整块重算。挑**存起来占地方、重算又便宜**的东西重算，最划算。最典型的就是注意力权重 $P$：在 Llama 2 7B 里，$P$ 占每层激活的 61%（432 KB 里的 262 KB）；而算它的 FLOPs 只占总量的 8% 左右（[[02.4 训练的计算量为什么是 6ND]] §4.1 的表）。FlashAttention 就是只对 $P$ 做重计算：前向不存，反向时分块重算（[[05.5 FlashAttention：分块加在线 softmax]]）。

### 2.7 重计算能自己付账

多 33% 的计算听起来很贵，但第 8 讲第 62 页的标题是 "Activation recomputation can pay for itself (via memory)"。省出来的显存可以换来更大的 micro-batch，或者少切几份模型、少一些卡间通信。这些都能提高 MFU，往往能把多出来的计算赚回来。

## 3. 两种办法对比

| | 梯度累积 | 激活重计算 |
|---|---|---|
| 换的是什么 | 时间：$k$ 份串行 | 计算：多一次前向，最多 +33% |
| 激活降到多少 | 原来的 $1/k$ | 检查点 + 一段的激活 |
| 结果和原来一样吗 | 数学上一样，但要按 token 总数平均 | 完全一样，同样的计算再做一遍 |
| 什么时候用 | 想要的 batch 比装得下的大 | 一份 micro-batch 都装不下，或者想用更大的 micro-batch |
| 常见搭配 | 两者一起用，再加上第 8 讲的各种切分 | |

一句话：梯度是线性的，所以一批可以切成几份算完再加，用时间换显存，只要按 token 总数平均；反向要用的激活可以不存、到时候重算，用计算换显存。检查点要设在"段内存得多、入口存得少"的地方，Transformer 的块边界正是这样的地方。

## 练习

1. **推导.** 证明 §1.1 的等式。如果 $k$ 份大小不等，第 $j$ 份有 $B_j$ 个样本，每份的 loss 应该乘什么系数？
2. **估算.** $L=36$ 的玩具网络（每层激活 1 份，检查点也是 1 份），最优的 $k$ 是多少？峰值显存是不重计算时的百分之几？
3. **思考.** 把讲义玩具网络的每一层改成"$D\to4D$ 的矩阵乘法、ReLU、$4D\to D$ 的矩阵乘法、ReLU"。不重计算时每层存多少（以 $B\times D$ 为单位）？每层设一个检查点后呢？
4. **估算.** 用 §2.4 的数，Llama 2 7B 在每块设检查点、用 FlashAttention（不存 $P$）时，每 token 大约存多少字节？一条 4096 长的序列呢？

## 练习答案

1. $\nabla\mathcal L=\frac1B\sum_i\nabla\ell_i=\frac1B\sum_j\sum_{i\in j}\nabla\ell_i=\sum_j\frac{B_j}{B}\nabla\mathcal L_j$。所以第 $j$ 份的平均 loss 要乘 $B_j/B$。大小相等时 $B_j/B=1/k$，就是代码里的除以 $k$。§1.3 的修正就是这个式子：每份求和，再除以总数 $B$。
2. $k=\sqrt{36}=6$，峰值 $36/6+6=12$ 份，不重计算是 36 份，约 33%。
3. 不重计算：第一个矩阵乘法存输入（1 份），第一个 ReLU 存输出（4 份，同时是第二个矩阵乘法的输入），第二个 ReLU 存输出（1 份，是下一层的输入，不重复计）。每层 5 份。每层设检查点后，每层只存输入 1 份，反向时临时重算一层 5 份。层数多时，显存约降到原来的 1/5。
4. 检查点每 token $32\times4096\times2$ 字节 = 262 KB。重算一个块（不存 $P$）$(10d+4d_{ff})\times2$ 字节 = 170 KB。logits 177 KB。共约 0.61 MB。一条 4096 长的序列约 2.5 GB，而不做这些时是 57 GB。
