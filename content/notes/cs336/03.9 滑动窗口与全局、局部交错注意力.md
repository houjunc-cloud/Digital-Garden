# 03.9 滑动窗口与全局、局部交错注意力

出处：CS336 第 3 讲（Tatsu Hashimoto），第 33、57、64–66 页。所属栏目：[[notes/cs336/index|CS336：从零构建语言模型]]。感受野和缓存的数字是本地算的。

**术语预备**
- **全注意力（full / global attention）**：每个 token 看它之前的所有 token。
- **滑动窗口注意力（sliding window attention, SWA）**：每个 token 只看它之前最近的 $w$ 个 token（包括自己），$w$ 叫窗口大小。也叫局部注意力。
- **感受野**：一个 token 的输出，最远能受到多远之前的 token 影响。
- **NoPE（no positional encoding）**：这一层完全不加位置编码。

## 0. 问题：全注意力太贵

讲义第 64 页："Attending to the entire context can be expensive (quadratic)." 长度为 $n$ 时，每层全注意力：
- **计算**：每个 token 和前面所有 token 做点积，共约 $n^2/2$ 对，随 $n$ 平方增长（[[02.4 训练的计算量为什么是 6ND]] §4.1：上下文到 128K 时，注意力的计算比所有矩阵乘法加起来还多）。
- **KV cache**：每层要存全部 $n$ 个 token 的 $k$、$v$，随 $n$ 线性增长（[[03.8 GQA 与 MQA：为 KV cache 省显存]] §2.1）。

GQA 只缩小了每个 token 的缓存，没有改变"随 $n$ 增长"这件事。这篇讲另一条路：**不看全部**。

## 1. 稀疏注意力与滑动窗口

讲义的思路："Build sparse / structured attention that trades off expressiveness vs runtime"。第 64 页的图来自 Child 等人（2019）的 Sparse Transformer：除了只看附近（带状），还可以每隔固定步长看一个（strided），或者看固定的几个"汇总位置"（fixed）。讲义列的使用者有 GPT-3、GPT-OSS、Gemma 4。

最简单、也最常用的是**滑动窗口**：第 $t$ 个 token 只看 $t-w+1,\dots,t$。

$$\text{掩码：}\quad M_{tj}=\begin{cases}0&0\le t-j<w\\-\infty&\text{其他}\end{cases}$$

每层的计算从 $O(n^2)$ 降到 $O(nw)$，KV cache 从 $O(n)$ 降到 $O(w)$：**不管上下文多长，缓存都封顶。** 生成时只要一个长度为 $w$ 的环形缓冲区，新 token 进来，最老的那个出去。

### 1.1 感受野随深度线性增长

只看最近 $w$ 个，是不是就看不到更远的东西了？不是。第 1 层里，位置 $t$ 从 $[t-w+1,t]$ 收集信息；第 2 层里，它再从这些位置收集，而这些位置在第 1 层已经各自收集过各自窗口里的信息。于是信息每过一层能多传 $w-1$ 步，和卷积网络一样。

我用布尔矩阵的幂验证过：窗口 $w=4$，堆 $L$ 层后，最后一个 token 能"看到"的最远位置恰好是往回 $L(w-1)$ 个：1 层 3 个，2 层 6 个……8 层 24 个。

按这个算，Mistral 7B（32 层、窗口 4096）最后一层的理论感受野约 $32\times4095\approx13$ 万个 token。

### 1.2 但"传得到"不等于"用得好"

信息要一层一层地接力，每一跳都要挤进一个 $d$ 维的向量里，和别的信息混在一起。要从 10 万个 token 之前精确地取回一句话，这条接力链太长、太拥挤。所以纯滑动窗口的模型在需要精确远程检索的任务上会吃亏。

## 2. 现在的标准做法：局部层和全局层交错

讲义第 65 页的标题是 "Current standard trick – interleave 'full' and 'LR' attention"。大部分层用滑动窗口，每隔几层放一层全注意力：
- 全局层负责远距离的信息，可以一步直达，不需要接力。
- 局部层负责附近的细节，又便宜。

讲义列的例子：
- **Cohere Command A**：每 4 层里有 1 层全注意力。"Long-range info via NoPE, short-range info via RoPE + SWA"：局部层用 RoPE，全局层不用任何位置编码。
- **OLMo 3**（第 66 页的配置表）：3/4 的层用滑动窗口，窗口 4096 个 token；RoPE 的 base 是 $5\times10^5$；YaRN 只用在全注意力层上。
- **Gemma 4**（第 66 页的示意图）：若干局部层之后接一层全局层，最后一层总是全局层；全局层上只对部分维度做 RoPE（p-RoPE），并且让 key 和 value 共用一份。
- **LLaMA 4、Gemma 3** 也是滑动窗口加全注意力的组合。Qwen 3.5 / Qwen3-Next 走得更远，把大部分层换成了线性注意力，这是第 4 讲的内容（[[04.2 Mamba-2、Gated DeltaNet 与混合架构]]）。

### 2.1 能省多少缓存

设比例为 $r$ 的层用窗口 $w$，其余是全注意力，上下文长 $n$，缓存是全注意力模型的

$$f=(1-r)+r\cdot\frac{\min(w,n)}{n}.$$

| 上下文 | $r=3/4$，$w=4096$ | $r=5/6$，$w=1024$ |
|---|---|---|
| 8K | 0.625（1.6 倍） | 0.271（3.7 倍） |
| 32K | 0.344（2.9 倍） | 0.193（5.2 倍） |
| 128K | 0.273（3.7 倍） | 0.173（5.8 倍） |

（第一列是 OLMo 3 的配置。第二列是 5 层局部配 1 层全局、窗口 1024，Gemma 3 的技术报告里用的是这个比例。）上下文越长省得越多，但有上限：$n\to\infty$ 时 $f\to1-r$，即 4 倍或 6 倍。那几层全局层的缓存最终会成为主体。计算量的节省同理。

## 3. 为什么全局层要换掉 RoPE

这一点把 [[03.4 位置编码：正弦编码到 RoPE]] §2.4 的外推问题串了起来。

**局部层永远不会外推.** RoPE 的外推失败，是因为低频维度在训练时没见过那么大的相对距离对应的旋转角。滑动窗口层里，$q$ 和 $k$ 的相对距离永远不超过 $w$。只要训练时见过长度 $w$，不管推理时上下文多长，这些层看到的旋转角都在训练范围内。**RoPE 放在局部层里是安全的。**

**麻烦只在全局层.** 所以各家都只在全局层上动手：
- **Command A**：全局层干脆不用位置编码（NoPE）。因果掩码本身就泄露了位置信息（第 $t$ 个位置恰好能看到 $t$ 个 token），模型仍然能推断出顺序。没有旋转角，也就没有外推问题。
- **OLMo 3**：全局层保留 RoPE，但只在这些层上做 YaRN 插值。
- **Gemma 4**：全局层只旋转高频的那几对维度（讲义第 33 页："only rotate high frequency pairs"）。外推出问题的正是低频维度，干脆不转它们，让它们只承载语义。这也和 [[03.4 位置编码：正弦编码到 RoPE]] §2.2 里"训练好的模型把最低频的维度当语义通道用"的观察一致。

## 4. 实现

```python
def sliding_window_mask(n, w):
    i = torch.arange(n)
    diff = i[:, None] - i[None, :]          # diff[t, j] = t - j
    return (diff >= 0) & (diff < w)         # True 的位置可以看：自己和之前的 w-1 个

# 用法：scores.masked_fill(~sliding_window_mask(n, w), float("-inf"))，再做 softmax
```

Python 要点：
- `i[:, None] - i[None, :]` 利用广播得到一个 $n\times n$ 的矩阵，第 $(t,j)$ 个元素是 $t-j$。
- `diff >= 0` 是因果掩码；再加上 `diff < w`，就是滑动窗口。

这样写只是改了掩码，计算量并没有省，因为 $n\times n$ 的分数还是全算了。真正省计算的实现（比如 FlashAttention 的窗口选项）会直接跳过窗口外的分块。

## 5. 总表

| | 全注意力 | 滑动窗口 | 交错（局部为主 + 少量全局） |
|---|---|---|---|
| 每层计算 | $O(n^2)$ | $O(nw)$ | 大部分层 $O(nw)$ |
| 每层 KV cache | $O(n)$ | $O(w)$，封顶 | 总体约降到全局层的占比 |
| 远距离信息 | 一步直达 | 逐层接力，$L(w-1)$ 远，精度差 | 全局层直达 |
| RoPE 外推 | 有问题 | 不会外推 | 只需处理全局层（NoPE、YaRN、部分 RoPE） |
| 例子 | 早期多数模型 | Mistral 7B | Command A、OLMo 3、Gemma 3/4、LLaMA 4 |

一句话：滑动窗口把每层的计算和缓存都封了顶，信息靠逐层接力也能传得很远，但传不精确；所以现在的做法是大部分层用窗口、每隔几层放一层全注意力负责远程直达，并且只在全局层上处理 RoPE 的外推问题，局部层天然不会外推。

## 练习

1. **估算.** Mistral 7B 有 32 层、窗口 4096。最后一层的理论感受野是多少？
2. **推导.** 证明 §2.1 的公式，并求 $r=3/4$、$w=4096$、$n=65536$ 时缓存是全注意力的多少。$n\to\infty$ 时呢？
3. **思考.** 为什么说 RoPE 放在滑动窗口层里"永远不会外推"？如果推理时把窗口从 4096 改成 8192，还成立吗？

## 练习答案

1. $32\times(4096-1)=131040$，约 13.1 万个 token。
2. 全注意力每层缓存 $n$ 个 token，窗口层缓存 $\min(w,n)$ 个，按层数加权平均再除以 $n$ 即得。$n=65536$ 时 $f=0.25+0.75\times4096/65536=0.297$，约 3.4 倍。$n\to\infty$ 时 $f\to0.25$，最多 4 倍。
3. 窗口层里相对距离 $|m-n|<w$，旋转角 $|m-n|\theta_j$ 的范围只取决于 $w$，和上下文总长度无关。训练时见过长度 $w$ 的距离，推理时就不会遇到新的角度。把窗口改成 8192 就不成立了：4096 到 8192 之间的距离对应的角度，训练时没见过，又回到了外推问题。
