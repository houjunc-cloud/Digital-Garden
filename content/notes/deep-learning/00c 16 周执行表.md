## 规则

1. **4 晚承诺 + 1 晚缓冲。** 每周排 4 个晚上（约 10 小时），第 5 晚留给溢出。TA 爆炸、论文卡住、单纯累，都从缓冲里出。**排满 5 晚的计划会在第三周崩掉。**
2. **每晚开始前写一句话**：今晚要让什么东西从红变绿（一个测试通过 / 一条曲线跑出来 / 一个数字量出来）。写不出这句话，说明今晚该做的是拆任务，不是开始写代码。
3. **每晚结束必须 commit**，哪怕是半成品，message 里写清楚卡在哪。这个 repo 就是 Log 10 里第四项产出（公开可验证）的载体，**从第一周开始积累，不是最后补的**。
4. **卡住 45 分钟 → 强制换动作。** 去 [[00 外部资源地图]] 找第二个讲法、去读参考实现、或者开个 issue 写清卡点然后跳过。纯数训练出来的"死磕"习惯在这里是**负资产**：数学里死磕两小时常有回报，配环境死磕两小时纯亏。
5. **不许重写、不许优化、不许"先把架构设计好"。** 先让它跑通。

## GPU 与预算

现价（2026-09 查，Vast.ai spot，可被抢占）：**RTX 4090 $0.08/h · A100 80GB $0.20/h · H100 SXM $0.65/h**。on-demand 贵一档。

- **钱不是约束，忘记关机才是。** 几百刀在这个价位是几百到上千 GPU 小时，这 16 周用不完。唯一真实的失败模式是开着机去睡觉。
- **纪律**：开机前把要跑的命令写好 → 跑 → 立刻关 → 记进 `gpu-log.md`（时长、花费、跑了什么）。这个习惯本身就是 infra 岗要的东西。
- **spot 被抢占是特性不是 bug**：它逼你把 checkpoint / resume 写对，而那本来就是 A1 的要求。
- **4090 就够。** A1 的训练规模和 Triton kernel 开发都不需要 H100。只有 W14 分布式要 2 张卡，租几小时。
- 分配：Phase 1 训练 ≈ $40，Phase 2 kernel + 分布式 ≈ $80，其余留缓冲。

## Phase 0 · 地基（W1–W2，约 18h）

### W1｜09-08 → 09-11（4 晚，本周无缓冲）

- **晚 1** — 开一个 public repo `ai-lab`。装 `uv` 建环境。`git` 完整走一遍：branch → commit → push → 开 PR → merge 进自己的 repo。 → *绿灯：第一个 commit + 第一个 merged PR*
- **晚 2** — 注册 Vast.ai，租一台 4090 半小时，跑 `nvidia-smi` 和一个矩阵乘，**关机**。建 `gpu-log.md` 记第一条。 → *绿灯：花掉第一笔钱（几毛），并确认自己会关机*
- **晚 3** — 张量语义：shape / stride / `view` vs `reshape` / broadcast / dtype / device。**作业：写 10 个 `einsum` 表达式**（batch matmul、attention 分数、outer product、trace、双线性型…），每个配一个 `assert` 对照手写循环。 → *绿灯：10 个 assert 全绿*
- **晚 4** — pytest：把那 10 个 assert 改写成正规测试，接上 GitHub Actions。 → *绿灯：GitHub 上一个绿勾*

### W2｜09-14 → 09-18

- **晚 1** — 空文件开始手写标量 autograd（`Value` 类，支持 `+ * tanh`），能对两层 MLP 求梯度。**先自己写，写不出来再看 [Karpathy micrograd](https://karpathy.ai/zero-to-hero.html)。**
- **晚 2** — 和 `torch.autograd` 对拍：随机 100 个表达式，梯度误差 < 1e-6。 → *绿灯：对拍脚本全绿*
- **晚 3** — 从空文件写 MLP 训 MNIST。**不许抄教程**：自己写数据循环、训练循环、打印 loss。
- **晚 4** — 接 wandb 重跑；`breakpoint()` 和 `torch.profiler` 各用一次。 → *绿灯：一条 wandb 曲线 + 一份 profiler 输出*

## Phase 1 · CS336 A1：从零搭语言模型（W3–W8，约 60h）

Clone [`assignment1-basics`](https://github.com/stanford-cs336/assignment1-basics)。**测试全红是起点，不是问题。**

### W3｜BPE tokenizer
最容易被低估的一块，给整周。晚 1–2 写 BPE 训练（pre-tokenization、pair counting、merge），晚 3 写 encode/decode 过 round-trip，晚 4 在 TinyStories 上训一个 10k vocab 并量压缩率。

### W4｜数据管线
晚 1 用 profiler 找 BPE 训练的瓶颈（慢得离谱是正常的）；晚 2 把语料 tokenize 成 `uint16` memmap；晚 3–4 写 batching（随机采样 context window）+ 测试。

### W5｜Transformer 零件（逐个写，逐个过测试）
晚 1 Linear / Embedding / RMSNorm｜晚 2 RoPE｜晚 3 SwiGLU + 数值稳定的 softmax｜晚 4 scaled dot-product attention + causal mask。

### W6｜组装 + 优化器
晚 1 MHA → TransformerBlock → 完整 LM｜晚 2 cross entropy（logsumexp 稳定版）｜晚 3 从零写 AdamW｜晚 4 cosine 调度 + gradient clipping。

### W7｜真的训起来
晚 1 训练循环 + checkpoint save/load（**必须能 resume**）｜晚 2 本地小规模跑通、loss 下降｜晚 3 租卡在 TinyStories 上正式训｜晚 4 采样，读它生成的东西。

### W8｜故意弄坏再修好

- 晚 1–2 — 故意搞坏三样：学习率大两个数量级 / 忘记 causal mask / 初始化 scale 错。**观察三条 loss 曲线各自长什么样。**
- 晚 3 — 写 `debugging-log.md`：把"loss 不降时的排查顺序"变成自己的 checklist
- 晚 4 — 按 checklist 把模型调到更好的 loss

> [!important] W8 不能跳
> Log 10 里第 2 项能力——"能 debug 一个悄悄坏掉的训练，**这条筛掉的人最多**"——整张表只有这一周在训练它。跑通了就往下走是浪费：**故意弄坏再修好，才是训练。**

## 三条会让这 16 周失败的路

1. **滑回读书。** 最可能的失败。某晚卡住了，去读讲义感觉舒服，然后一周过去了。对策是规则 4，而且换的动作里**不包括"系统性地读一章"**。
2. **想把代码写漂亮。** 纯数训练会让人想先把抽象设计对。A1 的目标是过测试，不是好架构。**能过测试的丑代码 > 设计到一半的漂亮代码。**
3. **把缓冲晚花掉当常态。** 缓冲是给意外的。连续两周靠缓冲赶进度 = 这张表排重了，该**砍内容**而不是加班——加班在博二可以，在博三博四会直接吃掉论文。
