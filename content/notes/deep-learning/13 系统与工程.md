# 13 系统与工程

> **原课完全没有这一块。**它看起来最"不数学"，但恰恰是现代论文里最难读懂的部分，而且它的核心内容——**算术强度、IO 复杂度、通信量分析**——是干净的组合优化与复杂度理论。不理解这一层，就无法判断一篇论文的贡献是算法的还是工程的。
>
> 前置：[[12 Transformer]]。

## 1. 硬件模型

**关键数字（以 NVIDIA H100 SXM 为例）：**

| 资源 | 带宽/容量 |
|---|---|
| 计算 (bf16 张量核) | ~990 TFLOP/s |
| HBM 带宽 | ~3.35 TB/s |
| HBM 容量 | 80 GB |
| SRAM (每 SM 共享内存) | ~228 KB，总计 ~50 MB |
| SRAM 带宽 | ~数十 TB/s |
| NVLink (卡间) | 900 GB/s |
| InfiniBand (机间) | ~400 Gb/s = 50 GB/s |

**算术强度（arithmetic intensity）** $I:=\dfrac{\text{FLOP}}{\text{字节访存}}$。

**Roofline 模型.** 实际吞吐 $=\min(\text{峰值 FLOP/s},\ I\times\text{带宽})$。**平衡点** $I^*=990\times10^{12}/3.35\times10^{12}\approx 295$ FLOP/byte。

- $I<I^*$：**访存受限（memory-bound）**，加速要减少访存而非减少计算。
- $I>I^*$：**计算受限（compute-bound）**。

> [!tip] 这一个不等式解释了本篇 80% 的内容
> - 矩阵乘 $A_{m\times k}B_{k\times n}$：FLOP $=2mnk$，访存 $\approx2(mk+kn+mn)$。当 $m,n,k$ 都大时 $I\sim O(\min(m,n,k))$ —— **计算受限，好**。
> - 逐元素操作（激活、加法、归一化）：$I=O(1)$ —— **严重访存受限**。
> - **推理时的解码**（batch=1，每次一个 token）：矩阵乘退化成矩阵–向量乘，$I=O(1)$ —— **严重访存受限**。这就是为什么 LLM 推理速度基本由显存带宽而非算力决定。
>
> 于是三条工程主线立刻清楚：**(a) 算子融合**（把逐元素操作合并进矩阵乘的 kernel，避免往返 HBM）；**(b) 提高 batch**（把矩阵–向量变成矩阵–矩阵）；**(c) 减少数据量**（量化）。

## 2. Tokenization

**BPE（Byte Pair Encoding, Sennrich et al. 2016）.**

```
初始词表 = 所有字节 (256 个)
重复 V-256 次:
    统计语料中所有相邻 token 对的频率
    把最频繁的对 (a,b) 合并成新 token ab, 加入词表
```

**性质**：贪心、无回溯；高频词成为单个 token，低频词被切成子词；**无 OOV**（字节级兜底）。

**BPE 是压缩算法。**词表大小 $V$ 与序列长度 $T$ 的乘积近似守恒——这是 [[03 信息论#42-kraft-与最优码长|Kraft 不等式]]的实际体现。典型现代 LLM 用 $V\approx 128\text{k}$–$256\text{k}$。

**tokenization 的坑（值得知道，因为它导致了很多"模型很笨"的假象）：**
- **数字**：`1234` 可能被切成 `12`+`34`，破坏位置价值。修复：强制数字逐位切分（LLaMA-3、多数现代模型采用）。
- **字符级任务**：模型看不到 token 内部，所以"strawberry 里有几个 r"这类问题困难——**不是推理缺陷，是表示缺陷**。
- **多语言不公平**：低资源语言的 token 效率差 2–5 倍，直接转化为更高的 API 成本与更短的有效上下文。
- **Glitch token**：训练中几乎没出现的 token，其 embedding 未被训练，触发异常行为（如著名的 `SolidGoldMagikarp`）。

**替代方案**：字节级（ByT5、MegaByte）、动态分块（BLT, Byte Latent Transformer 2024）。目前 BPE 仍是主流，因为序列长度的代价太大。

## 3. FlashAttention：IO 复杂度的胜利

**问题.** 朴素 attention 的实现：

```
S = Q @ K.T          # 写 T×T 到 HBM
P = softmax(S)       # 读 T×T, 写 T×T
O = P @ V            # 读 T×T
```

访存 $\Theta(T^2)$，计算 $\Theta(T^2d)$。当 $T\gg d$ 时算术强度 $I\sim d$，远低于 $I^*$ —— **访存受限**。而且 $O(T^2)$ 的显存占用直接限制了上下文长度。

**FlashAttention（Dao et al. 2022）的解决方案：分块 + 在线 softmax，永不写出 $T\times T$ 矩阵。**

**核心技巧：在线 softmax（Milakov–Gimelshein 2018）。** softmax 需要全局的 $\max$ 与 $\sum$，看似不能分块。但可以增量更新：设已处理的块给出 $(m_1,\ell_1,O_1)$（当前最大值、指数和、部分输出），新块给出 $(m_2,\ell_2,O_2)$，则
$$m=\max(m_1,m_2),\quad \ell=e^{m_1-m}\ell_1+e^{m_2-m}\ell_2,$$
$$O=\frac{e^{m_1-m}\ell_1O_1+e^{m_2-m}\ell_2O_2}{\ell}.$$

**这是一个结合的 monoid 运算**，所以可以任意分块、任意顺序归约。

**算法.** 把 $Q$ 分成行块、$K,V$ 分成列块，双重循环，每次把块载入 SRAM，在 SRAM 内完成 $QK^\top$、softmax 更新、$PV$，只把最终 $O$ 写回 HBM。

**定理（IO 复杂度）.** 设 SRAM 大小 $M$。FlashAttention 的 HBM 访存量为
$$\Theta\Big(\frac{T^2d^2}{M}\Big)\quad\text{vs 朴素的}\quad\Theta(Td+T^2).$$
当 $M\gg d^2$（实际成立，$M\sim10^5$，$d\sim128$）时是**数量级**的改善。且这个界是**最优的**（Dao et al. 给了匹配的下界，用的是 Hong–Kung 红蓝卵石游戏的论证）。

> [!note] 为什么这是好的数学
> 这是一个**通信复杂度**结果，和 Hong–Kung (1981) 对矩阵乘的经典 I/O 下界同源。它说明：**在算法设计中，"多少次算术运算"是错的成本模型，"多少次数据移动"才对。**
>
> 而且注意 FlashAttention **不改变输出**——它计算的是精确的 attention。这与所有近似方法（Linformer、Performer）有本质区别，也是它被普遍采用而后者没有的原因。
>
> 反向传播不存储 $P$，而是重算（recomputation）——**用计算换内存**，因为计算便宜访存贵。

**FlashAttention-2**（更好的并行划分与 work partitioning）、**FlashAttention-3**（利用 Hopper 的异步与 FP8）继续把利用率从 ~35% 推到 ~75%。

## 4. 混合精度 {#混合精度}

| 格式 | 位数 | 指数位 | 尾数位 | 动态范围 |
|---|---|---|---|---|
| fp32 | 32 | 8 | 23 | $10^{\pm38}$ |
| fp16 | 16 | 5 | 10 | $10^{\pm5}$ |
| **bf16** | 16 | **8** | 7 | $10^{\pm38}$ |
| fp8 (E4M3) | 8 | 4 | 3 | $\sim10^{\pm2}$ |

**bf16 vs fp16**：bf16 与 fp32 **指数位相同**，动态范围一致，梯度不会下溢，**不需要 loss scaling**。代价是精度低（7 位尾数），但深度学习对精度不敏感（梯度本身有噪声）。**bf16 是现代训练的默认。**

**标准混合精度训练**：
- 前向/反向用 bf16（省一半带宽与显存，用张量核加速）；
- **主权重与优化器状态用 fp32**（Adam 的 $m,v$ 若用 bf16 会因累加误差损失信息）；
- 归约（all-reduce、softmax 内部、loss）用 fp32。

**显存预算**（$N$ 参数，AdamW）：
$$\underbrace{2N}_{\text{bf16 权重}}+\underbrace{4N}_{\text{fp32 主权重}}+\underbrace{4N+4N}_{\text{Adam }m,v}+\underbrace{2N}_{\text{梯度}}=16N\ \text{字节}.$$

**70B 模型需要 1.12 TB —— 一张 80GB 卡装不下，必须分布式。**这就是下一节的动机。

## 5. 并行策略

设 $P$ 张卡。

**(a) 数据并行（DP）.** 每卡持有完整模型副本，处理不同的数据切片，反向后 all-reduce 梯度。
- 通信量：每步 $2N$ 字节（ring all-reduce 的最优通信量是 $2N(P-1)/P$）。
- **限制**：显存必须装下整个模型 $16N$。

**(b) ZeRO / FSDP（Rajbhandari et al. 2020）.** 把优化器状态（stage 1）、梯度（stage 2）、参数（stage 3）**分片**到 $P$ 张卡。
- Stage 3 的显存：$16N/P$。
- 代价：前向/反向时需要 all-gather 参数（通信量增加 1.5 倍），但可以与计算重叠。
- **这是当前最常用的方案**（PyTorch FSDP）。

**(c) 张量并行（TP, Megatron-LM）.** 把单个矩阵乘切开。对 $Y=\mathrm{GeLU}(XA)B$：
- $A$ 按**列**切：$A=[A_1,A_2]$，则 $XA=[XA_1,XA_2]$，GeLU 逐元素，无需通信；
- $B$ 按**行**切：$B=[B_1;B_2]$，则 $Y=Y_1B_1+Y_2B_2$，**一次 all-reduce**。
- 每个 Transformer 块需 2 次 all-reduce（attention 一次、FFN 一次）。
- **通信量大**（每层每步 $O(T\cdot d)$），必须在 NVLink 域内（单机 8 卡）。

**(d) 流水线并行（PP）.** 按层切分到不同卡。
- **气泡问题**：朴素实现的空闲率 $=(P-1)/(m+P-1)$，$m$ = micro-batch 数。GPipe 用大 $m$ 减小气泡；**1F1B / interleaved** 调度进一步改善。
- 通信量小（只传激活），适合跨机。

**(e) 序列并行 / 上下文并行.** 沿序列维切分，用于超长上下文。Ring Attention 让 KV 块在卡间循环传递，通信与计算重叠。

**(f) 专家并行（EP）.** MoE 的专家分布到不同卡，需要 all-to-all 通信。

**3D/4D 并行.** 实际大规模训练组合使用：
$$P = \underbrace{P_{\mathrm{TP}}}_{\le 8,\ \text{机内}}\times\underbrace{P_{\mathrm{PP}}}_{\text{跨机}}\times\underbrace{P_{\mathrm{DP}}}_{\text{剩余}}\ (\times P_{\mathrm{EP}}).$$

**选择原则**：把通信量大的并行放在带宽高的链路上。TP 用 NVLink，PP/DP 用 InfiniBand。**这是一个明确的组合优化问题**，Alpa、Megatron 的自动并行搜索就是在解它。

**梯度检查点（activation checkpointing）.** 只保存部分层的激活，反向时重算其余。内存 $O(\sqrt L)$ 而非 $O(L)$（用平方根分块），代价约 33% 额外计算。**又一次用计算换内存。**

## 6. 混合专家（MoE）

$$y=\sum_{i\in\mathcal{T}(x)}g_i(x)\,E_i(x),$$
$\mathcal{T}(x)$ 是路由器选出的 top-$k$ 专家（典型 $k=1,2,8$），$g_i$ 是门控权重。

**卖点：参数量与计算量解耦。**总参数 $N_{\text{total}}$（所有专家），每 token 激活 $N_{\text{active}}\approx N_{\text{total}}\cdot k/E$。于是可以在固定 FLOP 下把参数量放大 10–100 倍。

**Scaling law 视角**：[[09 Scaling laws]] 说损失取决于 $N$ 与 $D$，而计算 $C\approx6ND$。MoE 让 $N$ 增长而 $C$ 不变，**打破了 $C=6ND$ 的关系**——这是它的全部意义。经验上 MoE 的等效稠密参数量约为 $\sqrt{N_{\text{total}}N_{\text{active}}}$ 量级（Clark et al. 2022 的 MoE scaling law）。

**核心难题：负载均衡。**路由器倾向于坍缩到少数专家（富者愈富）。解决方案：

- **辅助损失**（Shazeer et al. 2017）：$\mathcal{L}_{\text{aux}}=\alpha\cdot E\sum_i f_i P_i$，$f_i$=分配给专家 $i$ 的 token 比例，$P_i$=路由概率均值。这个乘积在均衡时最小（Cauchy–Schwarz）。
- **无辅助损失的均衡**（DeepSeek-V3）：给每个专家一个可学习偏置，按负载动态调整。避免辅助损失对主目标的干扰。
- **专家容量与 token dropping**：超出容量的 token 被丢弃（走残差连接）。
- **Expert choice routing**（Zhou et al. 2022）：反过来让专家选 token，天然均衡。

**通信**：all-to-all 把 token 送到专家所在的卡，算完再送回。这是 MoE 的主要系统开销。

**路由器的不可微性**：top-$k$ 是离散的。实践中直接用直通估计（用 $g_i$ 的梯度，忽略 top-$k$ 的不可微），有效但理论上不干净。

## 7. 推理优化

推理分两阶段，性质完全不同：

| 阶段 | 描述 | 瓶颈 |
|---|---|---|
| **Prefill** | 处理整个 prompt | 计算受限（大矩阵乘） |
| **Decode** | 逐 token 生成 | **访存受限**（矩阵–向量） |

**KV cache.** 生成第 $t$ 个 token 时，前 $t-1$ 个位置的 $K,V$ 不变，缓存起来避免重算。

**大小**：$2\times L\times T\times d_{\text{kv}}\times$ 精度字节。对 LLaMA-3-70B（$L=80$, $d_{\text{kv}}=8\times128$）、$T=8192$、bf16：
$$2\times80\times8192\times1024\times2\ \text{B}\approx 2.7\ \text{GB / 序列}.$$
**batch 32 就是 86 GB —— 超过模型本身。**KV cache 是长上下文服务的主要成本。

**优化手段：**

- **GQA / MQA**：多个 query 头共享一组 KV 头。GQA-8（8 个 KV 头而非 64 个）把 cache 减少 8 倍，质量损失可忽略。**现代模型标配。**
- **MLA**（DeepSeek-V2 的 Multi-head Latent Attention）：把 KV 压缩到低秩潜空间再缓存，压缩率更高。
- **PagedAttention / vLLM**：把 KV cache 按固定大小的"页"管理（借鉴操作系统虚拟内存），消除碎片，把内存利用率从 ~40% 提到 ~96%，并允许前缀共享（多个请求共用同一 system prompt 的 cache）。
- **Continuous batching**：请求完成后立刻替换新请求，而不等整个 batch 结束。吞吐提升数倍。
- **量化**：权重量化到 int8/int4（GPTQ、AWQ）。由于 decode 是访存受限，**量化直接线性提速**。KV cache 量化到 fp8/int4 同理。

**推测解码（speculative decoding, Leviathan et al. 2023）.**

用小模型（draft）生成 $\gamma$ 个候选 token，大模型**一次前向**并行验证全部。用**修正的拒绝采样**接受/拒绝：

对每个位置，以概率 $\min(1, p(x)/q(x))$ 接受 draft 的 $x$；若拒绝，从修正分布 $\propto\max(0, p(x)-q(x))$ 重采。

**定理.** 输出分布**精确等于**目标模型 $p$ 的分布。

*证明.* 直接验证：接受的概率密度是 $q(x)\min(1,p/q)=\min(p,q)$；拒绝的总概率是 $1-\sum_x\min(p,q)$，重采分布是 $\frac{(p-q)_+}{\sum(p-q)_+}$，而 $\sum_x(p-q)_+=1-\sum\min(p,q)$。两部分相加得 $\min(p,q)+(p-q)_+=p$。$\square$

**加速比**：期望接受长度 $\approx\frac{1-\alpha^{\gamma+1}}{1-\alpha}$，$\alpha$ 是单 token 接受率。实测 2–3 倍，**无质量损失**。

> [!tip] 为什么这个技巧能存在
> 因为 decode 是访存受限的：**验证 $\gamma$ 个 token 与验证 1 个 token 的时间几乎相同**（都是把权重从 HBM 读一遍）。推测解码把闲置的算力换成了速度。这是 roofline 分析的直接应用。

## 8. 对数学家的建议

这一层看起来是纯工程，但它的核心是三个可形式化的问题：

1. **通信复杂度**（FlashAttention 的 IO 下界、all-reduce 的最优性）——这是经典的理论 CS。
2. **组合优化**（并行策略搜索、算子调度、MoE 路由）——整数规划。
3. **数值分析**（低精度训练的误差累积、量化的最优比特分配）——这一块理论最薄弱，实践中全靠经验，**有明显的空白**。

而且：**读现代论文时，区分"算法贡献"与"工程贡献"是必要技能。**很多号称的架构改进实际是系统优化（能在同样时间内跑更多步），反之亦然。
